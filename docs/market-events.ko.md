# 청산 관측과 경제 일정

시장·기록 → 시장 지표에 공개 자료 기반 기능 두 가지를 추가했다. 회원가입이나 개인 거래소 API 키 없이 사용한다.

## 청산 관측

- Bybit 공개 선형 선물 WebSocket 하나를 서버에서 공유한다. 지원하는 연구 종목 23개의 USDT 계약에 `allLiquidation.{symbol}`을 구독한다. 첫 조회 시 연결하며 화면은 10초마다 조회한다.
- 1·5·15분의 관측 건수, 롱·숏별 파산가격 환산액, 최근 최대 50개 기록을 제공한다. Bybit `S=Buy`는 **롱 포지션 청산**, `S=Sell`은 숏 포지션 청산이다. `p`는 **파산가격**이다. 따라서 `v × p`를 실제 체결대금으로 부르지 않는다.
- 구독 성공 전에는 0건으로 단정하지 않는다. 구독 확인, 20초 heartbeat, 60초 응답 공백, 재연결 지수 지연(최대 30초)을 처리한다. 관측 구간 전체가 연속 연결로 덮이지 않거나 저장 한도로 누락된 경우 불완전 구간으로 표시한다.
- 메모리 보관은 15분·최대 20,000건이다. 메시지 1MB 제한, 최근 512개 동일 메시지 재수신 중복 방지, 유효한 종목·시각·수량·가격만 수용한다. 한 메시지 내 같은 필드의 별도 행은 보존한다.
- 서버 재시작 시 기록은 초기화된다. 거래소 이전 기록 복원, 모든 거래소 합산, 24시간 시장 전체 청산 통계는 제공하지 않는다. 거래소 자체의 누락까지 검증하는 완전성 보장은 아니다.
- 심플 화면은 관측 규모와 방향의 쉬운 설명, 전문가 화면은 실제 기록표와 연속 연결·재연결 정보를 제공한다.

출처: [Bybit all liquidation stream](https://bybit-exchange.github.io/docs/v5/websocket/public/all-liquidation), [공개 WebSocket 연결](https://bybit-exchange.github.io/docs/v5/ws/connect).

## 경제 일정

- [미국 노동통계국 공식 ICS](https://www.bls.gov/schedule/news_release/bls.ics)와 [연방준비제도 FOMC 공식 일정](https://www.federalreserve.gov/monetarypolicy/fomccalendars.htm)을 고정된 주소에서만 읽는다. 공식 사이트의 임의 링크·스크립트를 실행하지 않는다.
- BLS의 Eastern 시각은 `America/New_York` 시간대와 서머타임을 검증해 UTC로 저장하고 한국 시간으로 표시한다. ICS 줄 접기·수정 차수·취소를 처리하며 모호한 시각, 지원하지 않는 반복 일정 등은 생략한다.
- FOMC는 공식 문서의 연도·월·회의일 범위만 추출한다. 발표 시각이 없는 회의에는 임의의 시각을 붙이지 않는다. 해석할 수 없는 날짜 형식은 추측하지 않는다.
- 조회 시 기관별로 최대 1시간 캐시를 재사용하며 동시 조회를 합친다. 실패는 1분 후 재시도한다. 마지막 성공 자료는 최대 24시간까지 '이전 자료'로 표시하고 그 이후에는 제외한다. 한 기관 실패로 다른 기관을 숨기지 않는다.
- 심플 모드는 향후 30일의 FOMC와 주요 물가·고용 발표를 가까운 순서로 보여준다. 전문가 모드는 7·30·90일과 기관별 필터를 제공한다.
- 예상치, 발표 결과, 영향도 점수, BLS·FOMC 이외 기관 일정은 제공하지 않는다. BLS 연간 일정이 아직 게시되지 않았다면 새해 일정이 적거나 없을 수 있다.

### BLS 접근 차단 시 무료 수집 경로

Railway와 GitHub 실행 환경 모두 BLS 직접 요청에 HTTP 403을 반환했다. 우회 주소나 유료 API 대신, 접근 가능한 [뉴욕 연준 공식 경제 일정](https://www.newyorkfed.org/research/calendars/nationalecon_cal.html)에서 BLS 발행 링크가 확인된 주요 7종(CPI, 고용보고서, PPI, JOLTS, 고용비용, 생산성·비용, 수출입물가)을 수집한다. 뉴욕 연준 경유 자료는 BLS 전체 발표 목록과 다르며 화면에서 출처와 범위를 구분한다.

- 공개 저장소의 표준 GitHub Actions 실행 환경으로 매 6시간 수집을 시도한다. [공개 저장소의 표준 실행 환경은 무료](https://docs.github.com/en/billing/concepts/product-billing/github-actions)이며 새 유료 API·서버·요금제를 추가하지 않는다. 저장소를 비공개로 바꾸면 게시 작업을 중단한다. 기존 Railway 운영 비용은 별도다.
- 검증된 공개 일정만 `calendar-data` 브랜치의 `bls.json`에 저장한다. 인증 정보·사용자 정보는 저장하지 않는다. 기존 GitHub의 임시 작업 토큰만 사용하며 PR 검사에는 쓰기 권한이 없다.
- 서버는 BLS 직접 조회가 실패하면 고정된 공개 JSON 주소를 읽는다. 원본 수집 시각을 유지하며 12시간 초과는 이전 자료, 24시간 초과는 사용 불가로 처리한다. 수집 실패는 마지막 정상 저장본을 덮어쓰지 않는다.
- 현재 월부터 최대 4개월의 게시된 달력을 확인하고 향후 90일 이내 일정을 보관한다. 미공개 월의 공식 404 응답에서 멈추며 화면에 확인 범위를 표시한다. 월 이름·날짜·발행기관·시각이 맞지 않으면 수집을 실패 처리한다.
- GitHub 예약 실행은 지연될 수 있고, 공개 저장소에서 장기간 활동이 없으면 예약 실행이 중지될 수 있다. 최신 수집 시각과 실패한 작업을 확인하고 필요하면 Actions의 수동 실행을 사용한다. 자동 갱신 중단을 실시간 최신 상태로 표시하지 않는다.
- 수집 확인: `node backend/research/collectCalendar.mjs`. 게시: 해당 Actions의 `publish-calendar` 작업. 게시에는 유효한 공개 저장소와 임시 쓰기 토큰이 필요하다.

## 운영과 검증

`GET /api/research/liquidations?asset=BTC`, `GET /api/research/calendar`를 사용한다. 기존 출처 허용·로컬 접근 제한을 유지하며 공개 캐시 조회는 별도 분당 900회 예산과 달력 동시 조회 16개 제한을 둔다. 이 조회가 기존 과거 시세·지갑 API의 예산을 소진하지 않는다. 프로세스 종료 및 개발 서버 종료 시 연결·타이머를 닫는다.

검증 범위: 청산 방향 해석, 동일 메시지 재수신, 연결 공백·복구, 잘못된 입력·보관 한도, DST 전환·취소 일정·공식 HTML, 독립적인 공급원 오류·캐시 만료, 심플/전문가 UI·필터·조회 실패 시 과거 기록 구분. 실제 BLS·FOMC 응답과 Bybit 23개 종목 구독 성공도 확인했다.
