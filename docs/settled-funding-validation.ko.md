# 실제 정산 펀딩비를 포함한 신호 검증

2026-10-28: 시장·기록 → 신호 탐색 → **비용·구간 검증**에서 기본 선택인 ‘실제 정산 기록 반영’으로 실행한다. 기존 Binance 공개 API와 서버를 사용하며 새 유료 공급원·계정 키가 필요 없다. 계좌에서 실제 낸 금액을 가져오는 기능이 아니라, 공개 정산 기록을 과거 가상 거래에 적용하는 기능이다.

## 계산과 표시

- 기존 70/30 분리·다음 봉 진입·수수료·불리한 체결 가정을 유지한다. 정산 시점의 `markPrice × fundingRate / 체결된 진입가격 × 100 × 방향`을 진입 금액 대비 비용으로 계산한다. 방향은 롱 +1, 숏 −1. 양수는 지급 비용, 음수는 수취액이다.
- 실제 정산 모드는 `dailyHolding`을 0으로 정규화한다. ‘직접 비용 가정’과 이중 차감하지 않는다. 기본 탐색·자동 감시의 비용 계산은 별도이며 여전히 실제 펀딩비를 반영하지 않는다.
- 정확한 봉 내부 청산 시각을 알 수 없다. 진입·종료 전후 15초 정산 오차와 종료 봉 안의 정산은 적용/미적용 범위로 계산한다. 여러 불확실한 정산의 독립적 최소·최대 합으로 만든 보수적 바깥 범위이며, 모든 체결·시장 위험의 절대 범위가 아니다.
- 각 거래의 평균 펀딩비, 지급/수취 의미, 제외 사례, 시점 불확실 사례, 거래별 비용을 제공한다. 표의 양쪽 도달 사례와 펀딩 시점 불확실 사례는 구분한다. 레버리지·복리·강제 청산·실제 계좌 수익률을 계산하지 않는다.

## 자료 범위와 실패 정책

- `GET /api/research/funding-settlements?asset=BTC&from=...&to=...`. 서버에서 종목 허용 목록, 정수·기간·미래 시각, CORS·읽기 전용·요청량을 검증한다. Binance USDⓈ-M 가격과 같은 종목·같은 거래소의 정산 기록만 비용에 사용한다. Bybit 필터 자료를 대신 사용하지 않는다.
- `GET https://fapi.binance.com/fapi/v1/fundingRate`의 양끝 포함 기간을 오름차순 1,000개씩 조회하고 다음 페이지는 마지막 시각 +1ms부터 시작한다. 최대 12페이지, 총 80초, 페이지당 8초·400KB. 한도 초과·중간 실패·잘못된 순서·중복·종목 불일치는 전체 실패다. 부분 기록을 완성으로 캐시하지 않는다.
- 최대 5,001일, 캐시 16개/5분, 동일 조회 공유, 동시 조회 3개, 상위 API 요청 5분당 최대 60개. API의 다른 소비자와 공유하는 한도에 여유를 둔다. 조회가 길면 범위를 줄이도록 안내한다.
- 검증 기간 시작 9시간 전부터 현재 완료 가격 기록까지 조회한다. 실제 정산 기록이 거래의 시작/끝을 둘러싸는 경우에만 계산한다. 아직 다음 정산이 없는 최신 구간, 양끝 미확보, 8시간 1분 초과 공백, 해당 거래에 필요한 정산 가격 누락은 사례를 제외한다. 조회 실패나 누락을 0원으로 처리하지 않는다. 정상적으로 전후 기록이 있고 보유 중 정산이 없으면 비용은 0이다.
- 8시간 1분 공백 검사는 큰 누락을 걸러내는 보수적 기준이다. 정산 주기가 변할 수 있어 모든 누락을 검출한다고 주장하지 않는다. 조회 완료는 공급자가 반환한 기간을 끝까지 읽었다는 뜻이다.
- 조건·종목·가격·비용이 바뀌거나 화면을 나가면 진행 중 조회를 취소하고 이전 결과를 숨긴다. 실패 시 다시 실행하거나 사용자가 직접 ‘비용 가정’으로 전환할 수 있으며 자동 대체하지 않는다.

## 재현과 검증

`investai-signal-validation-2`의 JSON에는 공개 `input.funding` 정산 기록, 정규화된 비용, 거래별 펀딩 범위, 제외 건수가 포함된다. 같은 버전에서 `validateSignalHistory(history, config, costs, contextsMap, funding)`으로 재현한다. 개인 계정·보유·임의 추가 속성은 내보내지 않는다.

테스트: 실제 정산가격/진입금액 비율, 롱·숏·음수 펀딩, 경계 15초, 봉 내부 종료, 누락 제외, 모드 간 중복 차감 방지, 미래 정산률과 앞 구간 분리, JSON 재현, 페이지 경계·중간 실패·응답 크기·요청 한도, UI 재시도·늦은 응답 취소를 검증한다.
