# 공개 포지션 연결과 위험 관측

사용자 범위 확정(2026-10-23): 분석·연동·알림을 우선 개발하며, 유료 구독과 결제는 후속 범위로 둔다.

## 이번 구현

`/research?mode=position`과 내 투자 화면의 연결 링크에서 시작한다. 심플 화면은 보유 방향·미실현 손익·확인할 기준을 카드로 설명하고, 전문가 화면은 수량·진입/평가가격·청산가·거리·레버리지·증거금 방식을 표로 비교한다. 모드를 바꿔도 연결 입력은 유지한다. 기존 직접 입력 계산과 일회성 공개 조회도 보존했다.

- Hyperliquid: 공개 주소의 기본 USDC 무기한 시장. HIP-3, 현물, 다른 하위 계정, 통합 계정 전체 증거금 위험은 포함하지 않는다.
- Lighter: 사용자가 지정한 숫자 계정 번호 하나의 무기한 포지션. 하위 계정을 임의로 선택하지 않는다. 거래소가 제공하지 않는 포지션 갱신 시각·설정 레버리지·증거금 방식은 추정하지 않는다.
- 30초 간격 독립 조회, 명시적 등록, 일시 정지/재개, 연결·기록 삭제, 공개 식별자를 포함하는 JSON 내보내기. PC와 프로세스가 실행 중이어야 한다.
- 처음 본 포지션은 `첫 연결에서 확인`으로 기록한다. 이후 새로 나타남·수량 변경·목록에서 사라짐을 구분한다. 목록에서 사라졌다는 이유만으로 강제 청산이나 확정 손익을 주장하지 않는다.
- 거래소 제공 청산가와 평가가격의 거리, 진입금액 대비 미실현 손실, Hyperliquid 설정 레버리지의 사용자 기준을 평가한다. 기본 입력은 청산 거리 5%, 손실 10%, 레버리지 기준 비활성이며 권장 투자 수치가 아니다. 기준은 등록 시 고정한다.
- 위험이 계속 유지되면 중복 기록하지 않는다. 회복 뒤 다시 기준에 도달하면 새 관측을 남긴다. 첫 연결에서 이미 기준에 해당하는 경우에도 위험 관측을 남긴다.
- 실제 연결 포지션에 반대 신호 감시를 묶을 수 있다. Binance USDT 선물 1시간 EMA 9/21 반대 교차를 사용한다. USDC 연결 계정과 다른 거래소·계약의 참고 분석임을 표시한다. 초기 관측 이후 새 교차만 기록하고, 24봉·상하 2%·비용 0.2% 관찰은 실제 계좌 손익과 분리한다.
- 해당 포지션이 사라지거나 방향이 바뀌면 반대 신호 감시를 종료한다. 포지션 자료가 오래되거나 연결을 멈추면 판정을 보류하고 진행 중 가격 관찰은 판정 불가로 남긴다. 재연결 뒤 기준을 다시 잡는다.

## 저장·시간·오류 처리

기존 `.local-data/monitor/ledger.json`에 `connections` 필드를 추가하며 이전 가격/신호 기록을 유지한다. 같은 저장소의 단일 작성자 잠금과 원자적 파일 교체를 그대로 쓴다. 잘못된 저장 파일은 덮어쓰지 않는다. 최대 동시 4개/보관 8개 연결, 연결별 200개 이벤트를 보관한다. 기록 한도에서 오래된 증거를 지우지 않고 감시를 멈춘다.

계정 조회는 고정 HTTPS API로만 전달하며 주문·서명·키를 사용하지 않는다. 주소와 결과를 별도 서버 캐시에 남기거나 로그에 출력하지 않는다. 주기적 연결을 명시적으로 등록한 경우에만 공개 식별자와 포지션을 이 PC에 저장한다. 기존 일회성 `/api/research/wallet`은 계속 저장하지 않는다.

API 응답 크기는 512KB로 제한하고 일부만 잘라 정상으로 취급하지 않는다. 잘못된 종목·수량·가격, 중복 포지션, 다른 계정 번호, Lighter의 미완료 페이지는 전체 조회 실패로 처리한다. 실패는 이전 포지션을 삭제하지 않는다. HTTP Date/Age와 Hyperliquid의 거래소 시각을 검사하며 PC 시각 차이는 거래소 자료의 지연으로 오인하지 않는다. Lighter는 응답 수신 시각을 표시하고 거래소 포지션 자체의 최신성을 보장하지 않는다.

120초를 넘는 관측 공백 또는 실패 후 복구에서는 해당 구간의 진입/종료 순서를 복원하지 않는다. 정상적인 두 조회 사이에서도 그 사이에 열렸다 닫힌 거래는 알 수 없다. 평가가격은 거래소 제공 포지션 금액을 절대 수량으로 나눈 값이다. 미제공 청산가를 가상의 공식으로 채우지 않는다.

개인 기록 API는 루프백·동일 출처에서만 접근하며 변경 요청에 JSON과 전용 헤더를 요구한다. 공개 Railway 서버에 개인 감시를 노출하는 구현이 아니다. 연결 삭제 중 진행 중이던 응답은 삭제된 연결을 되살리지 않는다.

## 알림과 검증 범위

앱 안의 기록은 기본 활성화된다. Telegram은 기존 서버 채널을 구성하고 해당 연결에서 사용자가 선택한 경우에만 발송한다. 발송 시도 전에 불확실 상태를 저장해 프로세스 중단 시 중복 발송하지 않는다. 주소·계정 번호·사용자 이름/메모를 메시지에 포함하지 않는다. 사용자가 선택한 포지션/위험 내용은 메시지에 포함된다. 실제 Telegram 전달은 이번 작업에서 실행하거나 검증하지 않았다.

이 문서의 범위는 공개 계정 연결이다. 후속 단계에서 [Binance·Bybit 읽기 전용 키 연결과 로컬 암호화 보관함](private-position-monitor.ko.md)을 추가했다. 실제 키 기반 연결 검증, OKX 등 추가 거래소, 인증된 다중 사용자 저장소, 클라우드 상시 감시, 채널별 사용자 설정은 남아 있다. 유료 구독·결제는 이번 우선 범위에서 제외한다.

검증: 백엔드 전체 90개 테스트 통과. 프런트엔드 전체 986개 중 주소 입력란 이름 충돌 1건을 발견해 수정했고 관련 화면·포트폴리오 27개 테스트 최종 재실행 통과. 나머지 985개는 전체 실행에서 통과했다. 타입 검사·빌드 통과, 새 린트 경고 없음(기존 3개 유지). 테스트 저장소는 임시 경로이며 사용자 감시 기록을 변경하지 않았다. 실 API 확인은 Hyperliquid 영 주소와 Lighter 시스템 계정 0의 빈 포지션 응답으로 수행했고 개인 계정은 조회하지 않았다.

## 확인한 1차 자료

- [Hyperliquid perpetuals info API](https://hyperliquid.gitbook.io/hyperliquid-docs/for-developers/api/info-endpoint/perpetuals): clearinghouseState, 기본 DEX 범위, 계정 통합 모드의 잔액 해석 제한.
- [Lighter 공식 Account API](https://github.com/elliottech/lighter-python/blob/main/docs/AccountApi.md): 공개 index 조회, active_only, 페이지 처리.
- [Lighter AccountPosition](https://github.com/elliottech/lighter-python/blob/main/docs/AccountPosition.md) 및 [DetailedAccount](https://github.com/elliottech/lighter-python/blob/main/docs/DetailedAccount.md): 포지션 필드와 계정 식별자.

브라우저 확인: 심플/전문가 전환 시 입력 유지, Lighter 계정 번호 입력 전환, 390px 화면 가로 넘침 없음, 브라우저 오류 로그 없음. 화면 캡처는 연결 전 상태이며 가상 포지션을 삽입하지 않았다. 사용자 연결·감시 기록에는 테스트 데이터를 등록하지 않았다.
