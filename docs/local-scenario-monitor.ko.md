# 검토 → 서버 감시 → 결과 기록

2026-10-23 구현. BAROBARA 벤치마킹에서 우선순위로 정한 검토·시나리오 연결과 브라우저 독립 감시의 첫 단계다. 모든 프리미엄 기능의 완성이나 운영 서버 배포를 뜻하지 않는다.

## 심플·전문가 화면

기존 앱의 간편모드·전문가모드 선택과 연결했다. 홈과 간편모드의 더보기에서 **시장·기록**으로 들어간다. 2026-10-23 재검토로 단순한 메뉴 축소 대신 이용 목적에 따라 화면 구조를 분리했다.

- 심플 시작 화면: **시장 살펴보기 → 내 생각 기록 → 알림·결과**의 흐름을 보여준다. 가격·시간별 차트, 연속된 완료 시간봉에서 구한 가격 변화와 거래량 해설, 지난 검토와 다음 행동을 먼저 보여준다. 빈 자료·누락 시간봉을 정상 흐름으로 설명하지 않는다.
- 기능 접근: **무엇이 궁금하세요?**의 질문 카드에서 지표, 손익·위험, 거래비용, 국내외 가격, 과거 검증을 모두 사용할 수 있다. 전문가 전환을 강제하지 않는다. 손익 계산은 단계별 입력과 비용을 풀어 쓴 결과로 제공한다. 상세 조건과 표는 펼쳐 볼 수 있다.
- 기록: 심플은 메모 시작 문구와 지난 생각·가격을 나란히 보여준다. 전문가는 당시 지표와 현재 수치를 자세히 비교한다. 감시는 기록 선택과 가격 조건 입력을 쉬운 말로 안내한다.
- 전문가: 아홉 분석 탭, 상세 수치·차트·계산 도구를 제공한다.
- 출처: 기본 화면의 **수신됨** 목록은 없앴다. **자료 출처·갱신 시각 확인**을 펼치면 제공처·시각·자료 상태와 해당 자료를 사용하는 도구로 이동할 수 있다. 연결 상태가 정상이라는 이유만으로 개별 값이 검증됐다고 표시하지 않는다.
- 두 모드는 같은 검토·감시 기록과 계산 로직을 사용한다. 같은 도구에서 모드를 바꿔도 종목과 작성 중인 메모·계산 입력값을 유지한다. 도구 자체를 이동하거나 새로고침하면 저장하지 않은 입력은 초기화될 수 있다.
- 자동 갱신 설정은 전문가 상단, 심플 하단의 **가격 새로고침 설정**에서 변경한다.
- 심플의 비용 비교·국내외 가격 비교·과거 흐름 도구는 입력 순서와 결과 해설을 나눠 보여준다. 비용은 수수료와 펀딩을 구분하고, 국내외 가격은 원화 환산 과정을 표시하며, 과거 흐름은 겹치지 않는 사례 수와 위·아래 도달/기간 종료 건수를 먼저 보여준다. 전문가 모드와 입력값·계산을 공유한다. 공개 지갑 주소·ETF 입력 초안도 같은 도구에서 모드를 바꾸면 유지한다.

## 사용 흐름

1. 연구실의 **검토·변화 기록**에서 현재 검토 기준을 저장하고 **최근 검토를 서버 감시로 연결**을 누른다. 기존 **내 투자 → 시나리오**에서도 **서버 감시로 연결**을 누를 수 있다.
2. 거래소와 가격 단위를 확인하고 진입 범위, 목표, 손절, 기간, 비용 가정을 입력한다. 저장한 검토 가격은 현재가가 아니다. 기본 비용 0.1%는 실제 거래소 수수료를 조회한 값이 아니다.
3. **이 조건으로 서버 감시 등록**을 누른다. 이후 화면을 닫아도 PC와 감시 프로그램이 실행 중이면 공개 시세 수집이 이어진다.
4. **조건 알림·결과**에서 등록 당시 메모·조건·지표, 관측 가격, 결과와 발송 상태를 확인한다. JSON으로 내려받을 수 있다.

원래 시나리오를 수정·삭제·일시정지해도 이미 등록한 서버 감시는 바뀌지 않는다. 서버 감시 화면에서 종료한 뒤 새 조건으로 등록한다. 기존 브라우저 시나리오 감시와 간단한 상·하단 알림은 계속 별도로 동작한다.

## 실행과 보관

현재 지원하는 UI 실행 경로는 저장소의 Vite 개발·미리보기 서버다. 기존 정적 Windows 데모 EXE와 GitHub Pages에는 감시 서버가 포함되지 않는다.

```powershell
# InvestAI/frontend 디렉터리에서
npm run build
npm run preview -- --host 127.0.0.1 --port 4191 --strictPort
```

`http://127.0.0.1:4191/research?asset=BTC&mode=alerts`에서 **감시 프로그램 연결됨**을 확인한다. 개발 중에는 `npm run dev`도 같은 API를 제공한다. Node.js와 기존 프로젝트 의존성이 필요하다. PC 재부팅 후 자동 시작, 절전 방지, 클라우드 배포는 설정하지 않았다.

감시 기록은 저장소 루트 `.local-data/monitor/ledger.json`에 보관하며 Git에서 제외했다. 개발 서버와 미리보기 서버는 이 파일을 공유하므로 하나만 실행한다. 다른 프로세스가 사용 중이거나 파일이 손상되면 저장을 중단하고 원본을 보존한다. 중단된 프로세스의 잠금은 다음 실행 시 확인 후 회수한다. 알 수 없는 잠금이나 손상된 기록을 자동 삭제하지 않는다.

브라우저 검토·시나리오의 원본은 기존 localStorage에 남는다. 서버로 등록한 항목만 파일에 복사된다. 원본 검토 최대 100개, 서버 동시 감시 최대 10개, 서버 기록 최대 200개다. 상한에서 오래된 근거를 자동 삭제하지 않고 신규 등록을 제한한다. 별도 장기 보관/정리 UI는 후속 작업이다.

감시 전용 CLI는 `InvestAI/backend`에서 `npm run monitor`로 실행하며 `127.0.0.1:8792`에서 API만 제공한다. `MONITOR_PORT`로 포트를 바꿀 수 있다. 이 CLI는 브라우저 화면 서버와 자동 연결되지 않으며 Vite 감시와 동시에 같은 저장소를 사용할 수 없다. 일반 사용은 위의 미리보기 경로를 사용한다.

## 가격과 결과의 정의

- Upbit는 지정 거래쌍의 최근 **체결 가격과 체결 시각**을 사용한다. 티커 응답 갱신 시각으로 오래된 체결을 최신으로 바꾸지 않는다.
- Binance 현물은 최근 체결 가격/시각, USDT 선물은 **마크가격/시각**을 사용한다. 원화 현물과 USDT 선물을 같은 종목으로 합치지 않는다.
- 거래소 HTTP Date와 Age를 기준으로 90초보다 오래된 자료, 미래 자료, 거래쌍 불일치, 잘못된 가격을 거부한다. 수집 주기와 경과 시간은 PC 수신 시각을 쓴다. 거래소 시각과 PC 시각이 다를 수 있다.
- 통상 15초 주기로 수집한다. 거래소 응답 지연이나 요청 제한 시 주기가 길어질 수 있다. 동일 거래쌍은 한 번만 조회한다.
- 첫 유효 가격은 기준으로만 저장한다. 이후 새 관측 가격이 진입 범위 안이면 진입 관측을 기록한다. 진입 대기 시간과 진입 후 관찰 시간은 각각 설정한 최대 시간이다.
- 목표·손절은 관측 가격 기준이다. 목표나 손절 가격으로 실제 체결했다고 가정하지 않는다. 두 수집 시점 사이의 경로와 최초 도달 순서는 알 수 없다.
- 기간이 지나면 다음 유효 관측을 기간 종료 가격으로 기록한다. 정확히 종료 시각의 가격은 아니다. 기간 이후 목표를 봤다고 목표 달성으로 바꾸지 않는다.
- 진입 후 90초 이상 공백이나 PC 시계의 큰 역행이 발생하면 **판정 불가**로 종료하고 변화율을 산출하지 않는다. 대기 중 공백은 첫 복구 시세로 기준을 다시 잡는다. 대기 기간 만료는 진입 없이 종료한다.
- 비용 반영 변화율은 관측 진입·종료 가격의 단순 롱/숏 변화율에서 입력한 왕복 비용을 뺀 값이다. 보유 수량·계좌 자산·레버리지·펀딩·실제 체결이 반영된 계좌 수익률이 아니다.
- 원래 근거는 등록 후 수정 API가 없고 SHA-256 식별값을 함께 보관한다. 로컬 파일 자체를 사용자가 바꿀 수 있으므로 외부 인증이나 위변조 방지 원장을 주장하지 않는다.

## Telegram 준비 상태

발송 어댑터와 발송 상태 기록을 구현했다. 실제 채널을 설정하거나 메시지를 전송하지 않았다. 기존 계정·개인키·거래소 계좌 연결도 사용하지 않았다.

운영자가 서버 프로세스 환경에 아래 세 항목을 안전하게 설정하고 재시작하면 채널이 활성화된다. 브라우저 코드와 `VITE_` 환경변수에 비밀값을 넣으면 안 된다.

- `INVESTAI_TELEGRAM_ENABLED=true`
- `INVESTAI_TELEGRAM_BOT_TOKEN`: 사용자가 관리하는 봇의 토큰
- `INVESTAI_TELEGRAM_CHAT_ID`: 알림을 받을 본인 대화의 숫자 ID

각 감시 등록에서 **Telegram으로 보내기**를 따로 선택해야 발송한다. 메모와 계좌 연결 ID는 메시지에 넣지 않는다. 발송 전 상태를 먼저 저장하고, 성공 응답이 확인되면 발송 완료로 바꾼다. 응답을 받지 못했거나 발송 중 프로그램이 종료된 경우 실제 전달 여부를 알 수 없으므로 **발송 여부 미확인**으로 남기고 자동 재발송하지 않는다. 실패 복구·재발송 UI와 채널 연결 마법사는 아직 없다. 발송 지연이 가격 수집을 막지 않도록 분리했다.

## 운영 범위

API는 루프백 접속, 로컬 Host, 동일 Origin, JSON과 전용 요청 헤더를 확인한다. 공개 시장 데이터 중계 서버에는 개인 감시 API를 추가하지 않았다. 로그인과 사용자별 저장소가 준비되기 전까지 외부에 노출하면 안 된다. 다른 기기의 기록 동기화, 클라우드 24시간 운영, 계좌 자동 동기화, 장기 전략 검증은 제공하지 않는다.

## 신호 조합 감시 추가 — 2026-10-23

신호 탐색에서 선택한 30개 신호·9개 시간봉·결합 범위·시장 조건을 그대로 등록할 수 있다. 브라우저와 서버는 하나의 `backend/research/signals.mjs` 계산 엔진을 사용한다. 기존 가격 관측과 독립적인 30초 타이머가 과거 봉을 조회하므로 느린 이력 조회가 15초 가격 감시를 막지 않는다. 실제 점검 간격은 공급원 응답 시간에 따라 길어질 수 있다.

- `/api/monitor/signals` 등록, `/api/monitor/signals/stop` 종료. 기존 API의 동일 주소·Origin·전용 헤더 검사를 그대로 적용한다.
- 첫 조회는 기준만 잡는다. 이후 새 완료 봉에서 미충족 → 충족으로 변할 때 기록하며, 같은 조건 유지·동일 봉 재조회·재시작으로 중복하지 않는다. 뒤늦게 불러온 오래된 신호는 새 알림으로 재생하지 않는다.
- 원본 설정·버전·식별값, 발생 봉 시각·가격·신호와 후속 결과를 기존 원장 파일의 `signals`에 추가 저장한다. 기존 가격 감시 자료는 보존한다. 동시 6개, 보관 40개, 감시별 이벤트 100개가 상한이며 자동 삭제하지 않는다.
- 관측 결과는 다음 봉 시가 진입 가정이다. 양 경계 동시 도달은 순서 불명, 누락 봉은 판정 불가, 종료 시 진행 중 결과는 사용자 종료로 기록한다. 실제 거래·계좌 손익이 아니다.
- ‘보유 방향의 반대 신호’는 사용자가 직접 선택한 롱/숏 방향을 사용한다. 실제 계좌나 기존 현물 잔고와 자동 동기화하지 않는다. 보유 방향과 같은 관점의 조건이 섞이면 등록하지 않는다.
- Telegram은 채널이 설정되고 등록 시 선택한 경우에만 발송한다. 전송 시도를 먼저 저장하고 불확실한 전송은 자동 중복 발송하지 않는다. 새 신호 발생 알림의 실제 채널 발송은 미검증이다.

신호 탐색은 최근 최대 5,000봉 범위이며 장기 검증된 전략 목록을 제공하는 기능은 아니다. 펀딩/OI/청산의 과거 조건, 연간 과열도, CEX 동기화와 클라우드 운영은 미구현이다.

## 검증

- 세부 계산 도구 개선 후 관련 4개 파일의 테스트 18개 통과. 비용·가격 환산 계산과 모드 전환, 빈 입력·잘못된 비용·시세 시각 불일치, 과거 사례 집계, 중첩 도구의 초안 유지, 검토 저장→감시 등록 흐름을 검증했다. 감시 등록 테스트는 모의 API를 사용했으며 새 감시나 외부 메시지를 만들지 않았다. 형식 검사와 빌드 통과, 린트는 기존 경고 3개다.
- 심플·전문가 재설계 후 관련 7개 파일의 테스트 50개 통과. 공유 기록·초안 유지, 쉬운 계산기 접근, 출처 접기·도구 연결, 누락 시간봉과 오래된 가격 처리, 가격·거래량 해설을 검증했다. 형식 검사와 빌드 통과, 린트는 기존 경고 3개다. 실제 브라우저에서 두 모드의 서로 다른 배치와 메모 유지도 확인했다. 신규 감시 등록이나 외부 발송 없이 기존 기록을 보존했다.
- 감시 엔진·시세 어댑터·HTTP/저장/재시작·발송 분리 테스트 18개 통과. 이전 시장 데이터/연구 API 테스트 27개 통과.
- 관련 프론트엔드 검증 98개 통과(회귀 실행과 수정 후 대상 재실행을 합한 고유 항목 수). 시나리오·보유 기록 연결, 기존 검토 흐름, 중복 요청 방지, 미연결 화면과 거래소·통화 구분을 포함한다.
- TypeScript 검사, 프로덕션 빌드 통과. 린트는 기존 경고 3개이며 새 경고 없음.
- 실제 공개 Binance 마크가격으로 기능 확인용 기록 1건을 등록하고 브라우저 탭을 닫았다. 브라우저 없이 진입 관측과 기간 종료가 저장됐고 다시 열었을 때 원래 근거와 관측 결과를 확인했다. 외부 발송은 꺼져 있었고 거래 주문은 없었다. 해당 기록은 테스트임을 표시한 메모와 함께 종료 상태로 보관한다.
