# InvestAI 2.0 — 1차: 내 코인

기준: `main`의 `eca829e` (PR #78). `feat/investai-v2-portfolio`에서 개발하며 main 변경·자동 병합·배포는 수행하지 않는다.

## 구현

- 기존 `/portfolio` 자리표시자를 ‘내 투자 > 내 코인’으로 교체한다.
- 업비트 KRW/BTC/USDT 마켓, 바이낸스 현물에서 카탈로그 종목을 선택한다. 거래소, 마켓, 종목 ID, 표시 심볼, 기준통화, 평단가, 수량을 저장한다.
- 기준통화는 선택한 종목에서 가져온다. 서로 다른 거래소/마켓의 같은 심볼을 동일 자산으로 합치지 않는다. 여러 기록은 별도 보유 기록으로 유지한다.
- 평단가와 수량 수정, 삭제 확인/취소를 제공한다. 종목 식별정보 변경은 삭제 후 재등록한다.
- 평단가·수량은 유한한 양수이며 매입금액의 오버플로/언더플로도 차단한다.
- 매입금액 = 평단가 × 수량; 평가금액 = 조회가 × 수량; 평가손익 = 평가금액 − 매입금액; 수익률 = (조회가 / 평단가 − 1) × 100.
- 기준통화별 개별 보유 평가만 표시한다. 환율 변환이나 이종 통화 총합은 제공하지 않는다.
- 시세 조회 시점, 모의/조회 시세를 표시한다. 시세가 없거나 계산이 유효하지 않으면 손익/수익률은 `—`로 표시하며 기록은 유지한다. 새로고침은 기존 시장 서비스 재조회 기능을 사용한다.
- 분석 링크는 종목 ID와 보유 기록 ID만 넘긴다. 분석 화면이 로컬 기록에서 평단가를 읽어 보유 검토/보유 목적을 초기화한다. 다른 종목 선택 시 이전 평단가가 전파되지 않는다. 분석 입력 변경은 저장 기록을 수정하지 않는다.
- 4개 핵심 메뉴: 홈(`/dashboard`), 종목 분석(`/my-analysis`), 내 투자(`/portfolio`), AI 탐색(`/ai-analysis`). 마켓/뉴스/데모는 ‘시장·자료’에 유지한다. 기존 기본 진입 경로·분석 엔진·관심종목·PC 실행 스크립트·의존성은 유지한다.

## 로컬 저장 정책

- 관심종목 키와 별개인 `investai.portfolio.v1`에 버전 포함 JSON을 저장한다.
- 저장 스키마와 ID 중복을 검사하고 최대 1,000개 기록을 허용한다.
- 손상 JSON, 미지원 버전, 읽기 차단은 변경을 중지하며 기존 원본을 덮어쓰지 않는다.
- 저장공간 부족/쓰기 차단은 실패를 표시하고 화면에 성공을 반영하지 않는다.
- 다른 탭의 변경 이벤트는 재조회하고 이전 편집을 취소한다. 쓰기 직전 원본 비교로 이미 바뀐 데이터를 덮어쓰지 않는다.
- localStorage는 원자적 다중 탭 트랜잭션 저장소가 아니다. 극히 동시적인 쓰기를 완전히 직렬화하지는 않으며, 협업/서버 동기화 용도가 아니다.
- 이 브라우저/사이트 주소에만 보관하며 암호화·계정 백업·기기 동기화는 없다. 브라우저 데이터 삭제 시 소실된다. 보유 기록을 서버나 AI에 전송하는 기능은 추가하지 않는다.

## 수용 기준 및 검증 근거

| 기준 | 검증 |
| --- | --- |
| 등록/재조회/수정/삭제 확인과 취소 | PortfolioPage 워크플로 + 저장소 CRUD 테스트 |
| 관심종목과 분리 | 별도 키와 기존 관심 데이터 보존 테스트 |
| 0/음수/NaN/무한대/금액 범위 검증 | 저장소 및 화면 입력 테스트 |
| 손상/미지원 버전 보존, 읽기/쓰기 실패 | 저장소 및 화면 quota 실패 테스트 |
| 다른 탭 변경 처리 | 원본 충돌 테스트 + storage 이벤트 편집 취소 테스트 |
| 이익/손실/보합, 시세 없음 | 계산 테스트 + 화면 시세 실패 테스트 |
| 분석에 저장 평단가 전달, 다른 종목에 유출 방지 | 분석 화면 통합 테스트 |
| 4개 핵심 메뉴와 기존 경로 유지 | 내비게이션, 언어, 사이드바 및 전체 앱 회귀 테스트 |

실행 명령: 프런트엔드 `npm run check`, `npm run test:proxy`, `node --test tools/local-ai/*.test.mjs tools/prepare-pages.test.mjs`, 백엔드 `npm test`.

Windows 샌드박스 내 테스트/빌드는 자식 프로세스 생성이 `EPERM`으로 차단되어 승인된 환경에서 재실행한다. 기존 린트 경고 3건과 500 kB 이상 청크 빌드 경고는 별도 개선 사항이다.

## 범위와 한계

현물 수동 보유 기록과 미실현 손익만 다룬다. 선물·레버리지·공매도·실현손익·수수료·세금·환율·자동 거래·거래소 계정 연동·다중 기기 동기화는 미포함이다. 계산에는 JavaScript 부동소수점을 사용하며 회계 원장 수준의 정밀도를 보장하지 않는다. 시세는 기존 서비스의 조회/캐시 정책을 따르며 연속 스트리밍 평가를 추가하지 않는다.

브라우저에서 화면 렌더링과 카탈로그 표시를 확인했다. 거래소 실 API 전체에 대한 수동 CRUD/E2E 검증은 완료하지 않았으며 자동화된 화면 테스트에서는 통제된 카탈로그를 사용한다. 모바일 실기기 확인은 후속 점검 대상이다. 2.0 전체 UI 교체와 분석 고도화는 후속 PR로 진행한다.
