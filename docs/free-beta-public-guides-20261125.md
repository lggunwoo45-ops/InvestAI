# Free beta publishing readiness

Baseline: deployed main `42f1fc6b3d92fde4d8b31625d988462614190a4d`.

Journey: open the existing free beta → read its service introduction / practical guides / privacy notice on the same public host without signing in or running JavaScript → return to the unchanged app routes → find a contact for feedback. Search engines must receive real robots and sitemap documents.

Acceptance:
- Keep the app's existing root and deep-entry behavior, records, pricing and calculation rules.
- Ship the existing original public documents with Cloudflare deployments; do not inflate article counts or claim traffic / advertising approval.
- Add a concrete guide to entry, waiting and excluded scan decisions, based on implemented rules.
- Preserve both advertising ownership tags without enabling ad or analytics scripts.
- Disclose Cloudflare hosting factually without claiming an unverified data location, retention period or executed contract.
- Prepare a launch order and reapplication gate based on actual usage evidence, clearly separate from vendor requirements. No paid domain, ad campaigns, trackers, new accounts or repeat publisher application.

## Launch and advertising order

Use the existing free address and current backend. First fix public-document delivery and the user journey; then invite a small real beta group, collect specific feedback, and correct defects. Keep practical guides current and share the public introduction in appropriate communities where promotion is allowed. Do not buy traffic, request ad clicks or count automated checks as audience growth.

After real usage exists, assess whether people return and whether acquisition comes from genuine sources. Existing hosting request counts may include bots and development checks and must not be presented as unique human visitors. Search Console measures search exposure/clicks rather than the complete audience; sitemaps help discovery without guaranteeing indexing or approval. No new analytics script is enabled by this change.

Revisit a publisher application only after the submitted URL is unambiguous, public content and core workflows function, and genuine audience/source evidence can be supplied. This is a project readiness gate, not a vendor's numerical minimum. No arbitrary visit or article quota guarantees approval. Do not repeatedly resubmit an unchanged site or reset existing AdSense review as part of these improvements.
