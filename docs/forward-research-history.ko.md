# 미래 검증과 연구 기록 보관

2026-10-28 구현 범위. 추가 유료 공급원·주문 실행·수익 보장은 포함하지 않는다.

## 조건 고정 미래 검증

신호 탐색 → 비용·구간 검증에서 과거 비교를 실행한 뒤, 이름·고정 왕복 비용·7/30/90일 기간을 정해 등록한다. 공개 사이트에서는 회원 로그인이 필요하며 서버가 관측한다. PC용은 감시 프로그램이 실행 중이어야 한다. 전체 기록은 감시 화면의 신호 기록에서 확인한다.

신호 조합, 시간봉, 조건 범위, 방향, 목표 폭, 관찰 봉 수, 파생 조건, 고정 왕복 비용과 검증 기간을 서버 시각·해시와 함께 저장한다. 등록 뒤 수정하지 못하며 새 조건은 별도 검증으로 등록한다. 실시간 판정은 최근 1,000봉을 사용한다. 과거 비교 조회 범위와 분리해 20,000봉을 반복 수집하지 않는다.

첫 조회는 기준만 설정한다. 이후 등록 시각 뒤에 시작해 완료된 봉에서 신규 사례를 찾으며, 겹치는 관찰 기간과 오래된 복구 신호는 제외한다. 다음 봉 시가 진입을 가정하고 고정 왕복 비용을 차감한다. 같은 봉에서 상하 목표를 모두 건드리면 손실~이익 범위로 포함한다. 진행 중·수집 공백·중간 종료 사례는 평균에 넣지 않는다. 예정 종료 전에 관찰을 끝낼 수 있는 신호만 등록하고, 종료 시점까지 결과를 확보하지 못한 사례는 판정 불가로 남긴다. 자료 수신 실패 중에도 기간 만료를 처리한다.

일반 신호 감시와 합쳐 활성 6개, 종료 40개, 검증별 최대 100건 한도를 공유한다. 종료·재시작·동일 요청 재전송은 기존 회원별 감시 저장과 중복 방지 정책을 따른다. 외부 알림은 발송하지 않는다. JSON에는 고정 조건과 개별 사례·성과 범위를 포함한다. 실제 펀딩 정산 비용은 **과거 비용 검증**에서만 제공하며, 미래 검증의 고정 비용에는 자동 추가되지 않는다. 계좌 손익·레버리지·강제 청산·놓친 전체 신호까지 측정하는 기능이 아니다. 7~90일 실제 운영 성과는 해당 시간이 지난 뒤에만 평가할 수 있다.

## 최대 20,000봉 과거 조회

심플·전문가 모드 모두 선택할 수 있다. Binance USDⓈ-M의 완료 봉만 역방향 페이지 조회한다. 10분봉은 연속된 5분봉 두 개로 만든다. 제공처의 상장 이력이 짧으면 실제 확보 수만 반환한다. 중간 요청이 실패하면 부분 성공으로 캐시하지 않는다. 최대 42페이지·80초, 조회기당 분당 120회 상한과 공유 중복 요청·최대 16개 캐시를 적용한다. 오래된 파생 자료·실제 펀딩은 각각의 별도 보관/조회 한도를 유지하며, 시세 확대가 누락된 지표의 복구를 뜻하지 않는다.

출처: [Binance Kline API](https://developers.binance.com/docs/derivatives/usds-margined-futures/market-data/rest-api/Kline-Candlestick-Data).

## 청산 시간별 이력

Bybit 한 거래소의 공개 스트림을 서버 시작부터 수집한다. 개별 이벤트는 15분, 시간별 롱·숏 환산 합계·건수·연결 확인 시간은 7일 보관한다. 지난 24시간 또는 7일의 **완료된 시간 구간**을 조회하며 현재 진행 중인 시간은 실시간 화면에 남긴다.

저장 위치는 `INVESTAI_RESEARCH_DIRECTORY` 또는 기존 `INVESTAI_CLOUD_DIRECTORY/research-history`의 SQLite 파일이다. 운영의 기존 영구 볼륨을 사용한다. 저장 경로가 없는 실행은 메모리만 사용하며 화면에서 표시한다. 수집권 임대로 배포 중 중복 수집을 막고, 동일 메시지는 재시작 뒤에도 중복 집계하지 않는다. 한 메시지에 포함된 동일한 별개 이벤트는 유지한다.

아무 관측도 없는 구간은 `null`, 연결이 확인됐지만 이벤트가 없는 구간은 0이다. 부분 연결은 실제 확인 밀리초로 표시한다. 과거 수집 전·연결 중단 기록은 복원하지 않는다. `S=Buy`는 청산된 롱 포지션, 금액은 수량 × **파산가격**으로 실제 체결대금과 다르다. 시장 전체 청산액으로 해석하지 않는다.

출처: [Bybit All Liquidation](https://bybit-exchange.github.io/docs/v5/websocket/public/all-liquidation).

## ETF 수급 수동 기록 저장

시장 지표 → ETF 수급 기록에서 BTC·ETH별로 `날짜,순유입 USD,출처`를 입력한다. 브라우저 저장 또는 회원별 서버 동기화를 사용한다. 같은 종목·날짜를 고치면 이전 값·출처·저장 시각을 최근 5회 보관한다. 동일한 값의 재저장은 버전을 올리지 않는다. 총 1,000일치·500KB 제한이며 잘못된 날짜·미래 날짜·입력 내 중복 날짜·출처 누락을 거부한다.

CSV는 최신 값, JSON은 수정 이력을 내보낸다. CSV 출처 셀은 수식 실행을 막는다. 회원의 기존 '이 브라우저 기록 가져오기'를 선택하면 ETF도 합치되 같은 날짜의 회원 기록과 수정 이력을 우선한다. 손상된 기록이나 저장 실패 때 성공으로 표시하지 않는다. 없는 날짜를 0·휴장으로 추정하지 않는다. 자동 수급 수집·자료 진위 검증·유료 공급원은 아직 포함하지 않는다.
