# Sprint 10.18 이후 기능 후보

이 문서는 후보 비교 자료이며 구현 승인 문서가 아닙니다. 아래 기능은 Sprint 10.19에서 구현하지 않습니다.

## A. Beta deployment

후보 범위: Vercel 정적 프런트, Render/Railway 프록시, 환경 변수 설정.

- **가치:** 실제 외부 사용자 흐름, 브라우저 호환성, 선택형 프록시 실패 상태를 제한된 환경에서 검증할 수 있습니다.
- **위험:** 공개 URL 노출, 프록시 악용, CORS, 비용, 비밀값, 로그 개인정보, 법적 고지와 롤백 운영이 필요합니다.
- **시점:** 보안·법률·운영 체크리스트와 소유자가 확정된 뒤 진행해야 합니다. 단순 UI 개선보다 검증 가치는 높지만 성급한 공개 배포는 피해야 합니다.
- **권장 크기:** Large — 인프라 설계, 보안 헤더, 프록시 제한, 비밀 관리, 모니터링, 롤백을 별도 단계로 분리합니다.

## B. Daily Candidate UX polish

후보 범위: 더 명확한 빈 상태, 후보 설명 품질, 시장군 요약.

- **가치:** 현재 핵심 베타 흐름의 이해도와 첫 사용 성공률을 직접 개선합니다.
- **위험:** 설명을 강화하다 추천·예측처럼 보이거나 한 화면의 정보량이 다시 증가할 수 있습니다.
- **시점:** 외부 베타 전 빠르게 검증할 가치가 높습니다. 실제 사용자 관찰 또는 Claude UX 리뷰 결과를 먼저 반영하는 것이 좋습니다.
- **권장 크기:** Small–Medium — 문구/정보 계층 개선과 결정론적 시장군 요약을 분리합니다.

## C. Portfolio / holding review

후보 범위: 로컬 전용 관찰·보유 목록, 사용자가 직접 기록한 가격 추적, 브로커 미연동.

- **가치:** 후보 발견 이후 반복 사용 동기와 보유자 검토 흐름을 강화합니다.
- **위험:** 개인정보·투자내역 성격, Local Storage 손실, 개인화된 투자자문 오해, 성과 추적 기능으로 확장될 위험이 있습니다.
- **시점:** 법률·개인정보 경계와 데이터 삭제/내보내기 정책이 정리된 뒤가 적절합니다. 브로커 연동은 계속 제외해야 합니다.
- **권장 크기:** Medium–Large — 데이터 모델/안전 문구/저장 복구/삭제를 한 Sprint, UX를 다음 Sprint로 분리합니다.

## D. DART improvement

후보 범위: 검증된 고유번호 매핑 확대, 공시 원문 링크 개선, AI 요약 제외.

- **가치:** 한국 주식 검토의 실제 원천 근거 범위를 늘리고 Mock 데이터 한계를 보완합니다.
- **위험:** 잘못된 고유번호, 정정공시, 공시 유형 오해, API 한도와 서버 키 운영 문제가 있습니다.
- **시점:** 한국 주식 베타를 우선할 경우 단기 가치가 높습니다. 공시 의미를 긍정/부정으로 해석하는 기능은 미뤄야 합니다.
- **권장 크기:** Medium — 매핑 검증, 링크/상태 UX, 프록시 운영 테스트를 분리합니다.

## E. News improvement

후보 범위: 허용된 출처 확대, 명시적 관련 뉴스 매칭 개선.

- **가치:** 후보 이유와 시장 변화 맥락의 출처 투명성을 높일 수 있습니다.
- **위험:** 라이선스, 크롤링 정책, 허위 관련성, 중복 기사, 번역 비용과 프록시 보안 문제가 있습니다.
- **시점:** 출처 정책과 관련성 평가 기준을 먼저 문서화한 후 진행해야 합니다. 많은 출처보다 정확한 소수 출처가 우선입니다.
- **권장 크기:** Medium–Large — 출처별 어댑터와 관련성 평가를 각각 독립 Sprint로 둡니다.

## F. Real AI planning

후보 범위: Prompt 예산, 안전한 AI 요약, 직접 거래 신호 금지.

- **가치:** 긴 근거를 짧게 정리하고 사용자 질문에 맞춘 설명을 제공할 수 있습니다.
- **위험:** 환각, 투자자문 오해, 비용 폭증, 프롬프트 주입, 민감 데이터 전송, 모델 장애와 비결정성이 있습니다.
- **시점:** 지금은 구현보다 계약·입력 데이터·평가 기준·비용 한도를 설계할 시점입니다. 실제 호출은 법률/보안/평가 준비 후로 미룹니다.
- **권장 크기:** Large — 오프라인 평가, 안전 정책, 비용 제어, 공급자 경계를 여러 Sprint로 분리합니다.

## G. Compliance / legal review

후보 범위: 최종 문구 체크리스트, 유료 서비스 경계, 투자자문 위험 검토.

- **가치:** 제품 방향·유료화·개인화·공개 베타의 허용 범위를 조기에 명확히 해 재작업 위험을 줄입니다.
- **위험:** 법률 검토 없이 내부 판단만으로 안전하다고 결론 내리거나, 국가·시장별 규제 차이를 누락할 수 있습니다.
- **시점:** 공개 배포나 결제·실제 AI·보유 데이터 기능보다 먼저 진행해야 합니다.
- **권장 크기:** Medium — 내부 문구/기능 목록 준비 후 자격 있는 외부 전문가 검토를 별도 게이트로 둡니다.

## 제안 순서

1. Claude 코드·제품 방향 리뷰와 Blocker 정리
2. Compliance/legal 사전 검토
3. Daily Candidate UX 소규모 개선
4. 제한된 베타 배포 설계 및 보안 검토
5. DART 또는 뉴스 근거 확대
6. 보유자 흐름과 실제 AI는 별도 승인 게이트 이후 검토
