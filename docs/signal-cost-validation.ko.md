# 신호 비용·구간 검증

2026-10-26: 시장·기록 → 신호 탐색 → **비용·구간 검증**에서 현재 선택한 신호를 앞·뒤 구간에 따로 적용한다. 무료로 이미 조회한 최대 5,000개 완료 봉을 사용한다. 서버 변경, 새 데이터 계약, 주문, 유료 모델 호출은 없다.

## 화면과 사용 흐름

1. 신호 탐색에서 질문 또는 신호 조합을 선택한다.
2. 비용·구간 검증에서 한 번 거래 수수료와 불리한 체결 차이를 확인한다. 초기값 각각 0.05%는 사용자가 수정하는 예시다. 실제 계정 수수료를 조회한 값이 아니다.
3. 버튼으로 실행한다. 심플은 뒤 구간 요약, 비용 전후 평균, 앞·뒤 비교를 먼저 보여준다. 전문가는 3개 세부 기간과 최근 30개 사례·계산 근거를 펼친다.
4. 조건·비용·가격·파생 자료가 바뀌면 기존 결과와 내려받기를 보류하고 재실행을 요구한다. 탭이나 표시 모드만 바꾸면 입력과 결과를 유지한다.
5. 검증 기록을 JSON으로 내려받을 수 있다. 당시 완료 봉, 시점별 추가 조건 자료, 계산 조건·비용, 엔진 버전, 결과를 포함하며 계좌·보유·사용자 메모는 포함하지 않는다. 파일을 다시 읽는 화면은 이번 범위가 아니다.

## 구간과 미래 정보

최초 60봉은 지표 준비다. 그 이후 봉의 앞 70%와 뒤 30%를 고정 분리한다. 분할은 기간 최적화가 아니라 완료 봉 개수 기준이다. 두 구간은 같은 신호 설정을 사용한다. 뒤 구간 지표 계산에는 그 이전 가격만 사용할 수 있으며, 앞 구간의 관찰 기간이 뒤 구간에 걸치면 사례를 제외한다. 뒤 구간 끝에서 관찰이 완료되지 않은 사례도 제외한다. 같은 관찰 기간에 중복 진입하지 않는다. 공백 직후 지표 준비 60봉과 연속성이 깨진 미래 관찰은 사용하지 않는다.

기존 시점별 파생 필터의 `knownAt <= 판정 시각` 규칙을 유지한다. 선택한 지표 연결이 실패하면 실행하지 않으며, 개별 과거 시점에 자료가 없으면 제외 수를 표시한다. Binance 가격과 Bybit 파생 조건을 동일 거래소 자료로 취급하지 않는다.

전체 차트나 뒤 구간 결과를 이미 보고 조건을 바꿀 수 있는 탐색 화면이므로 **독립적으로 봉인된 검증이나 실전 적중률이라고 주장하지 않는다**. 30건 미만 안내는 통계적 충분성을 인증하는 기준이 아니다. 장기 시세 확장, 실제 펀딩 정산, 조건을 미리 고정한 미래 검증은 남아 있다.

## 체결·비용 가정

- 완료 봉 신호를 다음 봉 시가로 진입한다. 위·아래 가격 폭은 체결 차이 적용 전 진입 시가 기준이다.
- 롱 진입 가격은 위로, 청산 가격은 아래로 조정한다. 숏은 반대로 각각 불리하게 조정한다. 각 체결 금액에 한 번 거래 수수료를 적용한다.
- 진입 체결 금액 대비 순변화(%) = `방향 × (청산 체결가 / 진입 체결가 − 1) × 100 − 수수료% × (1 + 청산 체결가 / 진입 체결가) − 하루 보유비용% × 보유시간 / 24시간`.
- 관찰 중 봉 시가가 기준 가격을 이미 넘었으면 기준가가 아닌 그 시가로 청산한다. 양쪽 가격을 같은 봉에서 만나면 제외하지 않고 손실 기준 우선·목표 기준 우선의 두 결과를 모두 보관한다. 표시 범위는 통계적 신뢰 구간이 아니다.
- 가격 폭 미도달은 관찰 마지막 종가다. 종료 시각을 모르는 봉 안 체결은 그 봉 끝까지 보유비용을 차감한다. 이는 보수적인 가정이며 실제 펀딩 정산이 아니다. 추가 보유비용 초기값은 0이다.
- 기존 탐색의 왕복 `config.cost`는 새 결과에서 사용하지 않는다. 새 비용과 중복 차감하지 않으며 기존 탐색·서버 감시 계산은 바꾸지 않는다.
- 모든 사례를 같은 비중으로 평균한다. 계좌 누적 수익률·복리·레버리지·강제 청산·최대 낙폭을 계산하지 않는다. 결과 범위는 모든 비용과 체결 불확실성의 완전한 상하한이 아니다.

## 재현과 검증

계산 버전 `investai-signal-validation-1`, 기존 신호 버전 `investai-signals-1`, 선택 시 파생 판단 버전을 함께 기록한다. 내려받은 입력의 `history`, `config`, `costs`, `contexts`를 같은 버전의 `validateSignalHistory`에 넘기면 동일 결과가 재현된다.

자동 검증은 롱·숏 실제 체결 가정, 양쪽 수수료, 보유비용, 구간 경계 제거, 미래 가격 변경 시 앞 구간 불변, 불명 순서 범위, 가격 공백, 미완료 봉 거부, 파생 자료 지연, 기존 비용 중복 방지, 입력 변경 시 결과 보류, 모드·탭 전환, 내려받기와 계산 재현을 포함한다.

로컬 검사: 209개 파일 / 1,092개 테스트, 타입 검사와 배포 빌드 통과. 기존 린트 경고 3개 유지. 실제 BTC 1시간봉 1,000개로 결과 실행을 확인했으며 390px·320px 화면의 가로 넘침, 심플↔전문가 전환 시 결과 보존을 확인했다. 실제 휴대폰 운영체제 검증과는 구분한다.

가격 원자료와 펀딩 자료는 [Binance 공식 시장 자료 문서](https://developers.binance.com/en/docs/catalog/core-trading-derivatives-trading-usd-s-m-futures/api/rest-api/market-data)에 별도 항목으로 제공된다. 현재 저장된 Bybit 필터값을 Binance 포지션의 실제 펀딩 비용으로 대신 계산하지 않는다.
