# 업비트 분석 연결 복구

## 확인한 문제

종목 분석에서 1시간·4시간·일봉이 각각 웹소켓을 열었다. 카탈로그와 봉 조회도 같은 10.5초 요청 대기열을 사용하므로, 세 번의 연결 대기가 추가되고 화면은 이를 모두 ‘시세 연결 중’으로 표현했다. 소켓 연결·수신이 멈췄을 때의 제한 시간도 없었다.

2026-10-20 실제 KRW-BTC 원본 조회에서 1시간봉은 UTC 2026-10-18 18:00–22:00의 네 봉이 없었다. 4시간봉과 일봉은 연속적이었다. 거래소 응답에서도 빠진 구간이므로 클라이언트에서 가격을 만들어 채우지 않는다. 업비트는 체결이 없는 시간대의 봉을 생성하지 않는다고 명시하지만, 이번 공백의 운영상 원인까지 확인한 것은 아니다.

검증 PC의 시각은 업비트 HTTP Date·실시간 메시지 시각보다 약 5분 10초 앞섰다. PC 시각으로 거래소 봉의 마감 여부나 체결 신선도를 직접 비교하면 잘못 판정할 수 있다. PC 설정은 변경하지 않았다.

## 변경

- 동일 거래쌍의 모든 시간대가 한 웹소켓과 한 구독 요청을 공유한다. 초기 3개 시간대에 필요한 봉 조회 3회는 유지하고 웹소켓 연결 3회를 1회로 줄인다. 기존 10.5초 제한 간격을 유지한다.
- 필요한 캔들 채널을 처음에 함께 구독해 시간대 추가마다 구독 요청을 다시 보내지 않는다. 구독자별로 해당 시간대만 반영하며, 마지막 구독자가 나가면 연결·대기 작업을 정리한다. 서로 다른 기준통화는 분리한다.
- 실제 연결 시도는 15초, 연결 후 무수신은 90초를 기준으로 복구한다. 제한 대기열에서 기다리는 시간은 연결 제한 시간에 포함하지 않는다. 거래소 오류 메시지는 재연결로 처리하고 정상 시세로 간주하지 않는다.
- 재연결 후 봉 기록을 다시 읽어 연결 중단 동안 빠진 기록을 복구한다. 기록 확인과 유효한 시세 수신 전에는 분석을 재개하지 않는다. 기록 조회 실패는 기존 제한 대기열·재시도를 거쳐 복구하며 화면을 나가면 취소한다.
- 가격 수신 시각과 거래소 시각을 별도로 전달한다. 연결 신선도는 로컬 수신 시각, 봉 마감·체결 표본은 거래소 시각을 사용한다. 호가·알 수 없는 메시지·다른 마켓 메시지·잘못된 가격은 가격 신선도를 갱신하지 않는다. 늦게 참여한 구독자에게도 원래 수신 시각을 유지한다.
- 일봉은 UTC 0시 기준의 거래소 누적 OHLC·거래량을 사용한다. 연결 중 놓친 거래나 중복 체결을 누적해 일봉을 왜곡하지 않는다.
- 초기 준비와 재연결을 구분해 안내한다. 원본 봉 공백은 제외한 시간대와 구간을 표시하며, 정상 시간대 2개 이상이면 기존 기준으로 분석한다. 분석 임계값과 투자 데이터 저장 형식은 변경하지 않는다.

## 검증

- `npm run check`: 152개 파일, 832개 테스트 통과. 타입 검사·린트·빌드 성공.
- 이후 렌더 중 시간 조회로 추가된 린트 경고를 제거하고 린트·타입 검사·관련 분석 테스트·빌드를 재검증했다. 기존 린트 경고 3개와 500 kB 초과 번들 경고만 남는다.
- 공유 연결, 시간대·기준통화 분리, 부분 구독 해제, 최근 시세 재사용, 오래된 시세 거부, 중복 체결, 일봉 누적값, 오류 응답, 연결 무응답, 장시간 무수신, 재연결 시 기록 복구·취소, PC 시각 차이, 봉 공백 제외 후 부분 분석을 테스트한다.
- 로컬 브라우저에서 모의 데이터 없이 실제 업비트 BTC/KRW로 2/3 시간대 분석, 현재가·관심 구간·목표·가정 해제 기준 표시를 확인했다. 1시간봉만 원본 공백으로 제외되고 4시간봉·일봉은 분석에 사용됐다. 간편 모드에서 확인했다.

## 제한

정적 사이트에서 업비트에 직접 연결하므로 첫 준비는 여전히 약 1분 이상 걸릴 수 있고, 서버의 요청 제한·장애에 따라 더 길어질 수 있다. 연결 공유는 같은 페이지의 같은 거래쌍 범위이며, 여러 브라우저 탭·기기의 전체 요청을 합치지는 않는다. 실제 거래소 원본의 공백은 복구 대상으로 위조하지 않는다. 이 변경은 새 PR로 제공하며 main 직접 수정이나 자동 병합·배포는 하지 않는다.
