# 회원 이메일 인증과 비밀번호 재설정

## 현재 상태

이메일 인증 가입, 기존 회원의 이메일 연결, 이메일로 비밀번호 재설정 기능을 구현했다. **운영 발송 서비스와 발신 도메인은 미연결**이다. 사용자는 추가 결제 없이 준비하기로 했으므로 새 계정 생성·도메인 구매·유료 요금제·실제 이메일 발송은 진행하지 않는다.

설정 전에는 기존 아이디 가입·로그인·복구 코드가 동작하고 화면은 메일 발송 준비 중으로 표시한다. 메일 설정이 유효하면 신규 가입에 이메일 인증이 필요해진다. 기존 회원에게 소급해 로그인 제한을 걸지 않으며, 로그인 후 현재 비밀번호와 이메일 인증번호로 연결할 수 있다. 이미 인증한 주소의 변경·해제는 이번 범위에 포함하지 않는다.

## 사용 흐름

1. 가입: 아이디·이메일 입력 → 8자리 번호 요청 → 같은 화면에서 10분 안에 인증 → 비밀번호 설정과 가입 완료.
2. 기존 회원: 계정·알림 설정 → 본인 이메일·현재 비밀번호 입력 → 이메일의 번호 확인 → 계정 연결. 기존 기록을 복사하거나 덮어쓰지 않는다.
3. 비밀번호 찾기: 인증된 이메일로 번호 요청 → 같은 화면에서 번호·새 비밀번호 입력 → 새 복구 코드 보관 → 다시 로그인. 모든 기존 세션과 이전 복구 코드는 폐기한다.

비밀번호 생성 규칙은 기존 합의대로 8~128자·영문 대문자·숫자·특수문자 포함이다. 기존 비밀번호의 로그인 규칙은 변경하지 않는다. 이메일은 앞뒤 공백 제거와 소문자 정규화만 하며 점·플러스 주소를 임의로 합치지 않는다.

## 운영 연결

추가 서버나 패키지 없이 HTTPS 메일 전송 어댑터를 준비했다. 서버의 기존 영구 저장소와 암호화 설정을 사용한다.

| 설정 | 용도 |
| --- | --- |
| `INVESTAI_MAIL_PROVIDER=resend` | 명시적으로 메일 기능 사용 |
| `INVESTAI_MAIL_FROM` | 인증한 발신 도메인의 단일 이메일 주소 |
| `INVESTAI_MAIL_API_KEY` | 해당 발신 도메인의 발송 전용 키. 서버 비밀 설정으로만 보관 |

[Resend 무료 요금제](https://resend.com/pricing)는 확인 시 월 3,000통·하루 100통이며 [직접 관리하고 인증한 도메인](https://resend.com/docs/dashboard/domains/introduction)이 필요하다. 현재 소유 도메인이 없으므로 **추가 비용 없이 실제 발송까지 활성화됐다고 표시하지 않는다.** 향후 기존 발신 수단 확보 또는 도메인 준비 후 연결한다. 일반 회원에게 보내는 운영 경로로 제공업체의 시험 발신 주소를 사용하지 않는다.

설정 연결 후 실제 도착 확인은 지정된 시험 수신자와 별도 진행해야 한다. API 접수 성공은 받은편지함 도착을 보장하지 않는다. `/api/cloud/status`의 `emailAvailable`은 설정 준비 상태이며 실제 전달 성공률을 뜻하지 않는다. 설정은 앱 전체의 가입 요건에 영향을 주므로 검증한 뒤 활성화한다.

## 검증과 제한

- 번호는 암호학적 난수이며 저장소에는 서버 비밀키로 계산한 HMAC만 보관한다. 요청 식별자는 256비트 난수이고 DB에는 해시로 보관한다. 요청·인증번호는 URL, 로그, 프런트 저장소에 넣지 않는다.
- 번호당 최대 5회 시도, 10분 만료, 가입 아이디·용도·회원 소유자·비밀번호 버전 확인. 해시 계산 중 계정 변경과 동시 재설정을 재검사하고 한 요청만 성공시킨다.
- 기존 SQLite 계정 테이블은 유지하고 이메일·인증 요청·발송 제한 테이블을 추가한다. 원본 계정과 기록을 지우지 않는다.
- 발송 요청은 주소당 분당 1회·시간당 5회, 요청 주체당 시간당 10회, 전체 하루 80회·31일 구간 2,400회로 제한한다. 미등록 이메일 요청도 같은 예산을 사용하고 재시작해도 제한을 유지한다. 공유 네트워크에서는 일부 제한이 함께 적용될 수 있다.
- 미등록 주소와 등록 주소의 비밀번호 찾기 응답은 같은 형식이며 제공업체 요청을 기다리지 않고 응답한다. 미등록·미인증 주소로 복구 번호를 보내지 않는다.
- 제공업체 응답이 불명확하면 자동 재발송하거나 인증 완료로 처리하지 않는다. 재시작 중 전송이 끊기면 사용자가 다시 요청한다. 로그에는 고정된 실패 분류만 남긴다.
- 자동 검사는 가짜 메일 제공업체로 번호 생성·만료·중복·회원 분리·재시작·동시 변경·세션 폐기·발송 실패·화면 흐름을 검사한다. 실제 도메인 인증과 받은편지함 수신은 아직 검증하지 않았다.
