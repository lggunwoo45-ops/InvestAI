## 이번 코드에 포함한 동작

- InvestAI 아이디·비밀번호 가입/로그인, 일회용 복구 코드 재설정, 모든 기기 로그아웃.
- 회원별 연구실 검토·메모·신호 조합·브라우저 가격 조건 저장. 다른 기기에서 로그인하면 같은 기록을 읽는다.
- 동시 수정은 버전 충돌로 남기며, 두 사본을 내려받고 사용할 사본을 선택할 수 있다. 미전송 수정은 해당 회원의 탭 저장소에 임시 보관한다.
- 기존 비회원 브라우저 자료는 자동 업로드하지 않는다. 사용자가 가져오기를 선택하면 합쳐 복사하고 원본은 보존한다.
- 화면 종료와 관계없이 서버가 가격 통과·조건 진입/결과·신호·포지션 위험을 관측한다. 가격 관측은 약 15초, 신호·연결 포지션은 약 30초 주기다.
- 기존 Binance/Bybit 조회 전용 API 연결과 Hyperliquid/Lighter 공개 연결을 회원별 서버 저장소로 분리했다. 비공개 API 키는 기존 암호화 보관함을 사용하고 서버 재시작 후 다시 연다.
- 개인 Telegram 연결, 연결 해제, 테스트 발송, 등록별 발송 선택. 발송 결과가 불명확하면 자동 재발송하지 않는다.
- 심플 화면은 단계별 안내와 가격 알림을 먼저 보여주고 상세 감시는 펼쳐서 사용한다. 전문가 화면은 시장 살펴보기 / 분석 도구 / 기록과 감시로 묶었다.

내 투자·관심종목 등 기존 연구실 밖의 자료는 아직 기기별 저장이다. 회원 기록 다운로드에는 연구실 저장 자료와 가격 통과 기록이 포함되며, 상세 감시/포지션 기록은 각각의 내보내기 버튼을 사용한다.

## 서버 활성화

회원 기능은 기본적으로 꺼져 있다. 공개 코드 배포만으로 기존 방문자의 자료를 업로드하거나 Telegram 메시지를 보내지 않는다.

Node 22.13 이상에서 `backend/market-data/server.mjs`를 실행한다. 기존 Docker 이미지도 cloud/monitor 모듈을 포함한다. `node:sqlite`를 사용하며 추가 패키지 설치는 없다.

| 서버 환경 변수 | 설정 |
| --- | --- |
| `INVESTAI_CLOUD_DIRECTORY` | 영구 볼륨 안의 절대 경로. 컨테이너의 임시 파일시스템을 사용하지 않는다. 실행 사용자에게 쓰기 권한이 있어야 한다. |
| `INVESTAI_CLOUD_KEY` | 안전하게 생성한 32바이트 난수를 64자리 16진수로 보관. 재시작마다 새로 만들지 않으며 클라이언트 빌드에 넣지 않는다. |
| `INVESTAI_CLOUD_SIGNUP` | 신규 가입을 받을 때만 `true`. 기존 회원 로그인은 별도로 유지한다. |
| `RAILWAY_RUN_UID` | Railway의 `/data` 볼륨에서는 `0`. 시작 스크립트가 `/data/investai`의 소유권만 준비한 후 `node` 사용자로 전환하므로 웹 서버는 root로 실행되지 않는다. |
| `UPBIT_ALLOWED_ORIGINS` | 기존처럼 정확한 웹 출처만 허용. Pages 예: `https://lggunwoo45-ops.github.io` |
| `INVESTAI_TELEGRAM_BOT_TOKEN` / `INVESTAI_TELEGRAM_BOT_NAME` | 회원용 전용 봇. 다른 프로그램의 getUpdates 또는 webhook과 함께 사용하지 않는다. 둘 다 없으면 앱 감시 기록만 제공한다. |

프런트는 기존 `VITE_RESEARCH_URL`의 `/api/research`와 동일한 서버의 `/api/cloud`를 사용한다. 또는 기존 `VITE_UPBIT_RELAY_URL`에서 서버 출처를 사용한다. HTTPS로 제공한다.

### 배포 순서

1. `/data`에 영구 볼륨을 연결하고 `INVESTAI_CLOUD_DIRECTORY=/data/investai`로 설정한다. 암호화 키도 별도 보관한다. Railway 볼륨은 root 소유로 마운트되므로 `RAILWAY_RUN_UID=0`으로 시작 스크립트에 초기화 권한을 주며, 초기화 직후 서버는 `node` 사용자로 전환한다. 경로가 다르거나 심볼릭 링크이면 시작을 거부한다.
2. 단일 서버 인스턴스로 배포한다. DB의 실행 임대가 중복 감시를 막으며, 비정상 종료 뒤 재시작은 기존 임대 만료를 최대 35초 기다린다. 롤링 배포에서 두 인스턴스를 장시간 겹치지 않는다.
3. `/api/cloud/status`에서 HTTP 200, `enabled: true`를 확인한다. 저장소/키/중복 실행 오류는 HTTP 503으로 표시한다. 기존 시장 시세 health는 회원 기능의 준비 상태를 대신하지 않는다.
4. 두 개의 독립 탭/기기에서 같은 시험 계정으로 로그인해 검토 저장·수정 충돌·로그아웃을 확인한다.
5. 시험 가격 조건을 등록하고 브라우저를 닫은 뒤 최근 확인 시각과 기록을 확인한다. 종료한 감시가 재시작 뒤에도 종료 상태인지 확인한다.
6. 실제 외부 알림은 사용자 본인의 Telegram에서 봇 연결을 완료하고 테스트 메시지 수신을 확인한 뒤 사용한다. `Telegram 접수 확인`은 API 접수 결과이며 단말 수신을 보장하는 표시는 아니다.

SQLite 파일과 암호화 키를 함께 복구할 수 있어야 한다. 실행 중 파일 하나만 복사하지 말고 SQLite 온라인 백업 도구를 쓰거나, 서버 종료 후 볼륨 전체를 일관되게 백업한다. 암호화 키 변경은 기존 보관함을 열 수 없게 하므로 별도의 재암호화 절차 없이 교체하지 않는다. 이전 버전으로 롤백할 때 볼륨을 지우지 않는다.

현재 가입은 베타 50명, 세션은 12시간, 회원당 단순 가격 감시는 동시 10종목 / 누적 100조건 / 조건당 100이벤트로 제한한다. 기록 한도는 화면에서 안내하며 마지막 이벤트 이후 감시를 종료한다. 상세 감시와 거래소 연결은 기존 한도를 유지한다. 무제한 가입·다중 서버 확장·조직 계정 관리용 설계는 아니다.

## 아직 완료라고 표시하지 않는 범위

자동 ETF 확정 수급, 1년치 복합 과열도, 추가 거래소, 검증된 장기 전략 성과와 주식·원자재 확장은 별도 데이터 연결과 검증이 필요하다. 기존 수동 입력·현재 관측·봉 기반 시뮬레이션을 그 기능의 완성으로 간주하지 않는다. 유료 결제는 합의대로 이번 범위에서 제외했다. 후속 개발로 Bybit 청산 관측과 BLS·FOMC 경제 일정을 추가했으며, 제공 범위와 제한은 [시장 일정·청산 관측 문서](market-events.ko.md)를 따른다.

이 변경은 회원별 저장과 지속 감시를 연결한 코드이며, BAROBARA 전체 기능의 동일성을 검증한 결과가 아니다. 공개 서버의 영구 저장소·암호화 키·봇 활성화 및 실제 수신 확인은 별도 운영 단계다.
