# Sprint 10.19 — Internal Release Candidate QA Review

검토 기준: 현재 브랜치 `feature/sprint-10.19-claude-review-package`, 기준 커밋 `87a2e921713f8d2a6c8874cd6ae3ad6d0a077699`. 이 문서는 코드·정적 UI 구조·회귀 테스트를 기준으로 작성한 출시 전 내부 QA 결과다. 기능, 투자 로직, 후보 산정 로직은 변경하지 않았다.

## 1. 전체 평가

**판정: 내부 시연은 가능하지만, 외부 베타 출시는 조건부 보류(Conditional No-Go)다.**

Market Copilot의 핵심 흐름은 연결되어 있다. `/dashboard`에서 시장 상황을 훑고, `/ai-analysis`에서 업비트·바이낸스·코스피·코스닥·미국주식 중 한 시장군의 고정 후보를 확인한 뒤, `/my-analysis`에서 현재 판단과 근거를 검토하고, `/market`과 `/news`에서 원자료 맥락으로 이동할 수 있다. 후보는 시장군별 최대 5개로 제한되고, 저장된 순서와 항목은 후보 새로고침 전까지 가격 변화만으로 재정렬되지 않는다. 메인 흐름에서 단타·스윙·장기 선택은 제거되었고 전문가 모드의 접힌 상세 기준으로만 남아 있다.

그러나 공개 베타 전에 아래 세 가지 제품 이슈와 회귀 테스트 실패를 정리해야 한다.

1. “오늘 08:00”이라는 표시와 실제 로컬·지연 생성 모델의 차이를 사용자에게 정확히 보여줘야 한다.
2. 숫자로 표시되는 검토 범위 바로 옆에 “주문가가 아님”을 유지해야 한다.
3. 제품의 시작점, 베타 버전, 데모 설명이 현재 Daily Five 흐름과 일치해야 한다.

추가로 전체 회귀 테스트에서 Daily 시장군 새로고침 테스트 1건이 재현 가능하게 실패했다. 따라서 현재 커밋은 테스트 기준으로도 출시 후보 통과 상태가 아니다.

## 2. 출시 전 Blocker

### B1. “오늘 08:00 기준”과 실제 기록 날짜가 다르게 보일 수 있음

Daily 패널은 저장된 스냅샷의 `tradingDate`와 관계없이 항상 **“오늘 08:00 기준 기록”**이라고 표시한다. 앱을 08:00 전에 열면 이전 날짜 기록을 유지하도록 설계되어 있으므로, 전날 기록이 오늘 기록처럼 보일 수 있다. 카드의 “기록 시점”은 실제 `generatedAt`을 사용해 같은 화면에서 08:00 기준과 생성 시간이 달라 보일 수도 있다.

또한 현재 구현은 서버가 08:00에 다섯 시장군을 일괄 생성하는 구조가 아니다. 사용자가 08:00 이후 해당 시장군을 열고 카탈로그가 준비되었을 때 그 시장군을 로컬에서 생성한다. 따라서 공개 문구는 “매일 08:00에 생성”이 아니라 **“가장 최근 로컬 08:00을 기준으로, 첫 열람/새로고침 시 생성된 기록”**이라는 실제 동작을 반영해야 한다.

출시 전 최소 조치 제안:

- 패널 제목에 실제 `tradingDate`를 표시한다.
- 이전 날짜이면 “이전 기준 기록” 상태를 명시한다.
- `basisAt`과 `generatedAt`을 “기준 시점”과 “생성 시점”으로 분리한다.
- 서버 스케줄러가 생기기 전에는 “08:00 자동 생성”으로 홍보하지 않는다.

### B2. 후보 카드의 숫자 검토 범위에 비주문가 안내가 빠짐

`ReviewRangePanel` 자체에는 **“판단 보조용 검토 범위이며, 주문가나 수익 보장이 아닙니다.”**가 있지만, 후보 스냅샷 카드에서는 `showSafety={false}`로 숨겨진다. 패널 상단의 일반 문구 “판단 보조 정보이며, 거래 지시나 수익 보장이 아닙니다.”는 존재하지만, 사용자는 세 개의 구체적인 숫자 범위를 주문 가격처럼 해석할 수 있다.

출시 전 최소 조치 제안:

- 후보 목록 위에 한 번만이라도 “아래 숫자는 주문가가 아닌 근사 검토 범위”라는 문구를 노출한다.
- 또는 각 compact `ReviewRangePanel`에 짧은 비주문가 안내를 복원한다.
- 숫자 범위의 명칭과 스타일은 행동 버튼이나 주문 입력처럼 보이지 않도록 유지한다.

### B3. 공개 릴리스 식별 정보와 현재 제품 설명이 일치하지 않음

사이드바는 아직 `v0.6.2`를 표시하지만 Demo는 `Market Copilot 1.5 Beta`를 표시한다. Demo 스크립트와 제품 설명에는 현재 메인 흐름에서 뒤로 이동한 “기간 구분”과 “계획 구간” 표현이 반복된다. 실제 제품과 설명 자료가 다르면 기능이 깨진 것보다 신뢰에 더 큰 영향을 준다.

출시 전 최소 조치 제안:

- 하나의 사용자용 베타 버전 표기를 정하고 사이드바·Demo·문서에서 통일한다.
- Demo 스크립트를 “시장군 → 오늘의 최대 5개 후보 → 내 종목 분석 → 현재 판단/검토 범위 → 근거 확인” 흐름으로 교체한다.

### B4. Daily 시장군 새로고침 회귀 테스트 실패

요청된 전체 테스트에서 `src/app/App.test.tsx`의 **“refreshes only the selected daily market bucket”**가 실패했다. 후보 데이터가 준비되어 활성화되어야 할 **Refresh today’s candidates** 버튼이 제한 시간 안에 활성화되지 않았다. 해당 테스트만 다시 실행해도 같은 실패가 재현되므로 일회성 전체 스위트 간섭으로 처리할 수 없다.

현재 테스트는 기본 LIVE 카탈로그 경로가 테스트 환경에서 후보를 준비해 줄 것이라고 가정한다. 외부 연결 가능 여부 또는 공급자 fallback 상태에 따라 버튼 활성화가 달라진다면 Daily 후보 핵심 회귀 테스트가 환경 의존적이라는 뜻이다. 다음 수정에서는 실제 네트워크를 쓰지 않는 카탈로그 fixture/provider를 명시적으로 주입해 테스트를 결정적으로 만들고, 동시에 오프라인/공급자 실패 시 사용자가 보는 빈 상태와 재시도 경로를 별도로 검증해야 한다.

## 3. 중요한 UX 문제

1. **AI Analysis 하단의 AI 사용량 및 플랜이 핵심 작업을 압도한다.** 실제 AI와 결제가 연결되지 않은 상태에서 세 개 요금제, 크레딧, 미래 기능 표가 Daily Five 바로 뒤에 길게 표시된다. 후보 검토를 마친 사용자가 다음에 해야 할 행동보다 미래 판매 계획이 먼저 보인다. 공개 베타에서는 Demo/Settings의 접힌 “향후 계획”으로 이동하거나 기본 접힘이 적절하다.
2. **Demo가 사용자 온보딩과 내부 운영 콘솔을 동시에 수행한다.** Getting Started, Limitations, Readiness, System Status, What works, 발표 스크립트, Health, Demo flow, Roadmap, Trust, Feedback questions, 발표 금지 표현이 한 페이지에 중복된다. 외부 사용자용 “시작하기”와 내부 발표자/QA 정보를 분리해야 한다.
3. **첫 진입의 우선 행동이 일관되지 않다.** 루트는 `/market`으로 이동하고, 사이드바 첫 메뉴는 Dashboard이며, 문서는 Market Radar를 첫 화면으로 권장하고, Demo에는 별도 시작 흐름이 있다. 한 개의 기본 시작점과 한 개의 주요 CTA를 정해야 한다.
4. **My Analysis는 선택 후 정보 우선순위가 약해진다.** 요약, 현재 판단, 검토 범위, 검토 목적, 기준 기록, 관심/보유 검토, Action Readiness, 상세 분석, 사용자 입력, 입력 요약, 최종 안전 문구가 연속된다. 간편 모드에서는 “현재 판단 → 이유 → 다음 확인 → 근거 보기”를 한 화면의 기본 순서로 더 강하게 고정할 필요가 있다.
5. **전역 헤더 상태가 페이지 문맥과 충돌한다.** Market 페이지를 떠나면 활성 시장 상태를 비우는 동작은 올바르지만, 전역 헤더가 Market/Public API를 “설정 안 됨”으로 보여 Dashboard·News에서 시스템 장애처럼 느껴질 수 있다. “이 페이지에서 사용 안 함”과 “연결 실패”를 구분해야 한다.
6. **News의 공급자 모드가 너무 기술적이다.** Mock, RSS Ready, Local Proxy, allowlist, server-side RSS 같은 용어는 QA에는 유용하지만 일반 베타 사용자에게는 깨진 설정 화면처럼 보일 수 있다. 간편 모드에서는 “데모 뉴스 / 실험적 실시간 소스” 정도로 축약하는 편이 낫다.
7. **한국어 화면에 영어 고정 문구가 남는다.** Dashboard의 주요 제목·설명·세션 요약 등 일부가 영어 상수다. 이중언어 준비를 표방하는 공개 베타에서는 주요 동선만이라도 언어가 일관되어야 한다.

## 4. 문구/안전성 문제

### 양호한 점

- **“판단 보조 정보이며, 거래 지시나 수익 보장이 아닙니다.”**는 짧고 목적이 명확하다. 후보 목록과 분석 결과의 공통 안전 경계로 유지할 가치가 있다.
- 후보를 “추천”이나 “신호”가 아니라 “관심 후보”, “기준 기록”, “검토”로 표현한다.
- 매수·매도·손절가·익절가·목표가를 긍정적 행동 라벨로 제시하는 화면은 확인되지 않았다. 일부 단어는 “매수·매도 신호가 아닙니다” 같은 명시적 부정 안내, 거래 체결 데이터 타입, 테스트/내부 계약에서만 사용된다.
- Mock, Limited, Unavailable 상태를 숨기지 않고 실제 데이터 한계를 설명한다.

### 보완할 점

- **“접근 검토 가능”**은 초보자에게 사실상 진입 허가처럼 들릴 수 있다. “추가 검토 조건 일부 충족”처럼 상태를 설명하는 표현이 더 안전하다.
- **“관심 등록”**은 실제 저장 동작처럼 보이지만 Practical Decision의 상태명일 뿐이다. “관찰 가치 있음” 또는 “관심 검토”가 기능 오해를 줄인다.
- **“수익 보호 검토 범위”**는 이익 실현 가격을 암시할 수 있다. “상승 후 재검토 범위”처럼 중립적인 관찰 표현이 안전하다.
- “오늘의 관심 후보 5개”는 실제 데이터 부족 시 5개 미만일 수 있다. “최대 5개”를 제목이나 보조 문구에 명시하는 편이 정확하다.
- DART와 News의 미설정 상태 설명은 이전보다 명확하지만, 기술적 설정 방법을 사용자 화면의 핵심 메시지로 내세우면 제품 실패처럼 보인다. “근거 없음/연결 안 됨”과 “분석 자체는 계속 사용 가능”을 먼저 보여주는 현재 방향은 유지하되 설정 세부는 접어야 한다.

이 문서는 법률 자문이 아니다. 공개 베타 전에는 한국어 투자 권유·투자자문 오인 가능성, 숫자 범위 표시, 개인 평균가격 입력, 면책 문구의 위치를 전문 법률/컴플라이언스 검토에 넘겨야 한다.

## 5. 코드 구조상 위험

1. **Daily 08:00은 브라우저 로컬 시간과 로컬 저장소에 의존한다.** 기기 시간대, 시계 오류, 저장소 삭제, 다른 브라우저/기기에서 서로 다른 “오늘”과 후보가 생긴다. 서버 스케줄러 전까지는 기능 한계로 명시해야 한다.
2. **AI Analysis가 아홉 개 시장 카탈로그를 한꺼번에 준비한다.** 선택한 시장군 하나만 보더라도 Upbit 3개, Binance 2개, 한국 2개, 미국 2개 카탈로그 훅이 모두 실행된다. 실데이터 공급자가 늘면 초기 네트워크 비용, 실패 표면, 렌더 비용이 커진다.
3. **사용자용 문구가 컴포넌트에 분산되어 있다.** 페이지별 `copy` 상수와 중앙 `uiText`가 혼재해 버전·안전 문구·번역이 쉽게 어긋난다. 출시 문구와 안전 문구는 중앙 정책 계층으로 모을 필요가 있다.
4. **후보 기록은 시장군당 최신 1개만 로컬 저장한다.** 이는 현재 범위에는 맞지만 감사 로그, 재현성, 날짜별 비교, 기기 간 동일성은 제공하지 않는다. 외부에 “매일 기록”으로 설명할 때 이 한계를 밝혀야 한다.
5. **화면 상태와 제품 상태가 섞여 있다.** 전역 Header는 현재 Market workspace의 활성 상태를 제품 전체 연결 상태처럼 사용한다. 공급자 상태, 페이지 활성 상태, 서비스 상태를 분리하지 않으면 오탐 표시가 반복된다.
6. **회귀 테스트는 구조를 잘 잠그지만 실제 출시 화면 품질을 대신하지 못한다.** 최대 5개, 한 목록, 저장 순서, 손상 저장소 복구 등은 테스트되지만 1366/1920/2560 실제 배치, 키보드 전 동선, 스크린리더 순서, 저속 네트워크 체감은 별도 수동 QA가 필요하다.

## 6. 사용자가 헷갈릴 가능성이 높은 부분

- “오늘 08:00 기준”인데 카드의 기록 시각이 08:00 이후로 표시되는 이유
- 08:00 이전에 전날 기록을 보고 있는지 오늘 기록을 보고 있는지
- 후보가 자동으로 생긴 것인지, 새로고침 버튼이 새 후보를 계산하는 것인지
- “현재가”는 바뀌는데 후보 순서가 바뀌지 않는 이유
- “지금 판단”과 “Action Readiness”가 서로 다른 판단인지 같은 근거의 다른 표현인지
- “접근 검토 가능”이 행동 권유인지 단순 추가 확인 상태인지
- 세 개의 Review Range가 주문 가격인지 참고 범위인지
- Dashboard, Market, AI Analysis 중 어디서 시작해야 하는지
- AI Analysis 아래 요금제가 현재 결제 가능한 상품인지 단순 계획인지
- Header의 “Not configured”가 앱 고장인지 해당 페이지에서 시장 연결을 쓰지 않는다는 뜻인지
- News의 Mock/RSS/Local Proxy 중 일반 사용자가 무엇을 선택해야 하는지
- DART 미설정이 해당 종목 분석 전체 실패인지 공시 근거만 없는 것인지
- Market Copilot 1.5 Beta와 사이드바 v0.6.2 중 어느 것이 현재 버전인지

## 7. 바로 고쳐야 할 작은 수정

아래는 투자 로직이나 후보 산정 로직을 건드리지 않는 작은 UI/문구 수정 제안이며, 사용자 승인 후 별도 Sprint에서 적용한다.

1. Daily 제목을 `2026-09-27 · 08:00 기준 기록`처럼 실제 날짜 기반으로 표시하고 이전 날짜 배지를 추가한다.
2. “오늘의 관심 후보 5개”를 “오늘의 관심 후보 · 최대 5개”로 바꾼다.
3. 후보 숫자 범위 위에 “주문가가 아닌 근사 검토 범위”를 한 번 노출한다.
4. “접근 검토 가능”을 “추가 검토 조건 일부 충족”, “수익 보호 검토 범위”를 “상승 후 재검토 범위”로 완화한다.
5. 사이드바 `v0.6.2`를 실제 베타 버전 정책과 일치시키거나, 확정 전에는 버전 표시를 제거한다.
6. AI 사용량 및 플랜을 기본 접힘으로 만들고 “향후 계획 · 현재 결제 불가”를 제목에 포함한다.
7. Demo의 기간/계획 구간 문구를 Daily Five와 현재 판단/검토 범위 흐름으로 갱신한다.
8. Header의 비활성 상태를 “Not configured” 대신 “Not active on this page” 의미로 구분한다.
9. News 공급자 상세 제어를 전문가/내부 QA 영역으로 접고 간편 모드에는 데이터 출처와 fallback 여부만 보여준다.
10. Dashboard의 고정 영어 핵심 제목을 현재 언어에 맞춘다.

## 9. 유지해야 할 방향

- 시장군 우선 구조: 업비트 / 바이낸스 / 코스피 / 코스닥 / 미국주식
- 선택 시장군당 한 개 목록, 최대 5개 후보
- 새로고침 전 항목과 순서를 고정하고 현재가는 참고 정보로만 갱신하는 구조
- 단타·스윙·장기를 초보자 메인 선택에서 제거하고 전문가 상세 기준으로 격리한 방향
- Practical Decision을 이유·다음 확인·주의와 함께 보여주는 구조
- Mock/Limited/Unavailable과 실제 출처를 숨기지 않는 데이터 품질 경계
- DART·News가 없어도 핵심 분석은 계속 사용할 수 있고, 없는 근거를 만들어내지 않는 방식
- 후보/시장/뉴스/내 분석 사이의 기존 InstrumentId 기반 연결
- 실제 AI, 거래, 계정, 결제, 백엔드가 없다는 정직한 베타 범위
- “판단 보조 정보이며, 거래 지시나 수익 보장이 아닙니다.”라는 공통 안전 원칙

## 10. 버려도 되는 방향

- 공개 사용자 화면에서의 대형 AI 요금제·크레딧 시뮬레이션
- Demo 한 페이지에 내부 QA, 투자자 발표 스크립트, 시스템 상태, 사용자 온보딩을 모두 쌓는 구조
- 현재 핵심 흐름과 맞지 않는 “기간 구분/계획 구간” 중심의 과거 데모 설명
- 모든 페이지에 동일한 베타·제한·안전 문구를 반복해 정보 자체를 보지 못하게 하는 방식
- “Not configured”, allowlist, proxy 같은 개발자 상태를 일반 사용자 핵심 상태로 노출하는 방식
- 로컬 지연 생성인데 서버 예약 생성처럼 보이게 하는 “매일 08:00 자동” 인상
- 데이터 근거가 부족한 상태에서 실제 AI, 자동매매, 수익 예측, 유료 추천을 먼저 확장하는 방향
- Dashboard, Market, Demo가 각각 첫 화면처럼 경쟁하는 정보 구조
