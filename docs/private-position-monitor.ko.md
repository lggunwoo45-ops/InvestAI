# Binance·Bybit 읽기 전용 포지션 연결

2026-10-23 로컬 구현. 분석·연동·알림 우선 범위의 다음 단계이며 결제는 포함하지 않는다. 실제 개인 계정 키와 Telegram 발송은 사용하거나 검증하지 않았다. 이 문서는 공개 배포나 실계정 연결 성공을 주장하지 않는다.

## 사용자 흐름

시장 리스크 연구실 → 포지션 → Binance 또는 Bybit → 이 PC의 보관함 만들기/열기 → 읽기 전용 HMAC 키 입력 → 보관·조회 동의 → 권한과 첫 포지션 조회 확인 → 연결 저장.

- 보관함 전용 비밀번호는 12~256자. 거래소 로그인 비밀번호를 받지 않는다. 입력한 키는 성공/실패 후 화면에서 비우며 브라우저 저장소에 넣지 않는다.
- Binance는 조회 권한을 켜고 거래·출금·내부 이체·범용 이체·선물 거래 등 쓰기 권한이 모두 꺼졌는지 확인한다. 필수 권한 필드가 없거나 새로운 활성 권한이 발견되어도 거절한다. 읽기 전용 키로 선물 API 접근을 거절하는 계정은 연결할 수 없다. 사용자를 거래 권한 활성화로 유도하지 않는다.
- Bybit는 `readOnly === 1`, 키 일치, ContractTrade의 Position 조회 권한을 확인한다. 메인넷의 시스템 발급 HMAC 키만 지원하며 RSA 키·테스트넷·지역별 별도 API 호스트는 지원하지 않는다.
- 계정 연결 전과 매 조회마다 권한을 재확인한다. 서버는 고정 HTTPS GET 경로만 호출하며 주문·취소·레버리지 변경·이체·출금 기능이 없다.
- 포지션은 기존 심플 카드/전문가 표, 위험 기준, 반대 추세 감시와 연결된다. USDT와 공개 계정의 USDC를 구분하며 합산하지 않는다.
- 보관함 잠금은 진행 중 요청을 취소하고 비공개 포지션 및 연계 신호 판정을 보류한다. 마지막 기록은 남긴다. 공개 계정 감시는 계속된다.
- 프로그램 재시작 시 잠기며 앱에서 비밀번호로 열어야 비공개 감시를 재개한다. PC와 프로그램이 실행되어 있어야 한다. 보관함 잠금은 기록 자체를 숨기거나 암호화하는 기능이 아니다.
- 연결 삭제 시 해당 암호문도 함께 삭제한다. 보관함 전체 삭제는 별도 두 번째 확인으로 모든 API 연결·포지션 기록을 삭제하고 연계 신호 감시를 종료한다. 공개 계정과 기존 신호 결과는 보존한다. 거래소에서 발급한 키의 폐기는 거래소에서 해야 한다.

## 범위와 데이터 해석

Binance USDⓈ-M 및 Bybit linear의 **USDT 무기한** 계약만 포함한다. 거래소의 상품 목록으로 계약 종류·기초자산·호가 및 결제 통화를 확인한다. 현물, 인버스, 만기 선물, USDC 계약, 다른 하위 계정, 포트폴리오 마진 전용 API는 포함하지 않는다. Bybit 통합 계정의 포트폴리오 마진에서 누락된 청산가·레버리지는 추정하지 않는다. 포지션 목록 조회는 계정 전체 증거금 위험 분석이 아니다.

- Binance V3 `positionRisk`의 마크 가격·진입가·미실현 손익·청산가를 사용한다. 레버리지와 증거금 방식은 별도의 `symbolConfig`에서 읽는다.
- Bybit는 포지션 목록의 모든 커서를 따라간다. 레버리지/청산가 빈 값은 미제공으로 남기고, 계정 모드에 따라 의미가 다른 `tradeMode`로 교차/격리를 추정하지 않는다.
- 같은 종목의 롱·숏을 각각 보존한다. 중복 종목/방향, 불명확한 상품, 잘못된 수량·가격, 페이지 반복 또는 미완료 응답은 전체 실패로 처리한다. 실패 때문에 이전 포지션이 사라진 것으로 기록하지 않는다.
- 마크 가격으로 청산 거리, 진입금액 대비 미실현 손실, 제공된 설정 레버리지 기준을 계산한다. 교차 청산가는 계정 상태에 따라 변하며 전체 계정의 안전성을 보장하지 않는다.
- 거래소 서버 시각으로 서명해 PC 시각 차이를 보정한다. 응답 Date/Age와 Bybit 응답 시각을 검사한다. 포지션 변경 시각은 현재 평가가격의 갱신 시각으로 사용하지 않는다. 화면에는 응답 수신 시각을 표시한다.
- 이전 공개 연결과 동일하게 조회 간 거래 순서·실제 체결·확정 손익을 복원하지 않는다. 반대 신호는 Binance 1시간봉 EMA 9/21 참고 분석이다.

## 보관과 처리

기존 단일 작성자·원자적 저장의 `.local-data/monitor/ledger.json`에 `vault`를 추가한다. 비밀번호에서 scrypt(N=32768,r=8,p=1,32-byte salt)로 키를 도출하고, 각 API 키 쌍을 AES-256-GCM의 독립 12-byte nonce로 암호화한다. 인증 부가 데이터에 레코드 ID와 거래소를 묶는다. 비밀번호와 복호화 키는 디스크에 저장하지 않는다. 세션 키 버퍼는 잠금 시 덮어쓰며 새 요청/진행 중 결과를 세대 번호로 차단한다. 자바스크립트 문자열의 즉시 메모리 삭제까지 보장하지는 않는다.

권한·첫 조회가 성공한 뒤 암호문과 연결을 한 번의 원자적 저장으로 추가한다. 저장 실패/잘못된 비밀번호/변조 시 성공으로 응답하지 않는다. 보관함과 연결의 불일치는 원본 보존 후 감시 중지로 처리한다. 보관함 열기는 분당 5회로 제한한다. 전체 연결 동시 4개/보관 8개 및 기존 기록 한도를 공유한다.

브라우저에는 보관함 설정/열림 상태만 반환한다. 암호문, 키, 비밀번호는 상태 응답과 연결 내보내기에 포함하지 않는다. 연결에는 무작위 키 레코드 ID만 남긴다. 외부 오류 원문·서명 URL·헤더를 화면이나 로그에 노출하지 않는다. 개인 API 요청은 15초 전체 제한, 크기 제한, 429/418 재시도 대기를 적용하고 리디렉션을 거절한다. 상품 목록만 캐시하고 개인 응답은 캐시하지 않는다.

로컬 루프백·동일 출처·JSON·전용 헤더 조건을 기존 API와 공유한다. 키는 입력한 브라우저에서 같은 PC의 로컬 서버로 전달된 뒤 해당 거래소의 조회 인증에 사용된다. 공개 호스팅에는 이 API를 설치하거나 노출하지 않는다. 이 구현은 다중 사용자 인증/키 관리 서비스가 아니다.

## 검증

격리된 임시 저장소와 가짜 거래소 응답으로 암호문 변조·잘못된 비밀번호·중복 키·저장 실패·재시작 잠금·진행 중 잠금/삭제·권한 재검사·실패 후 이전 기록 보존·USDT 구분·헤지 모드·전체 페이지·서명·서버 시각·요청 제한·오류 비밀값 제거를 검증했다. 사용자 감시 저장소에 테스트 키나 계정을 등록하지 않았다. 실제 키 기반 계정·지역/계정별 API 호환성 및 Telegram 전달은 미검증이다.

최종 확인: 서버 전체 100개, 화면 전체 988개 테스트 통과. 타입 검사·빌드 통과. 린트는 기존 경고 3개만 유지한다. 실제 미리보기에서 390px/1280px 화면의 가로 넘침 없음, 모드 전환 후 선택 거래소 유지, 보관함 설정 전 키 입력 비활성, 오류 로그 없음을 확인했다. 테스트용 화면 크기는 원래대로 복원했다. [보관함 화면](assets/private-position-vault-2026-10-23.png)은 개인 키·계정을 등록하지 않은 상태다.
