# BAROBARA 프리미엄 벤치마킹과 InvestAI 적용안

조사일: 2026-10-23, 한국 시간 기준. 공개 화면과 사용자가 로그인한 프리미엄 계정의 화면을 직접 확인했다. InvestAI는 현재 로컬 소스 기준으로 비교했다. 이 문서는 기능 조사와 구현 명세이며, 아래 제안 기능의 구현·배포 완료 보고서가 아니다.

## 1. 판단

BAROBARA에서 가져올 핵심은 **시장 확인 → 조건 선택 → 알림 설정 → 당시 근거와 이후 결과 확인**이라는 연결이다. 지표 페이지를 늘리는 것만으로는 이 흐름이 만들어지지 않는다.

InvestAI에는 관심종목 검토 이력, 보유 내역, 시나리오와 브라우저 알림이 이미 있다. 이를 연구실의 시장 자료와 연결하는 편이 새 관심목록·새 포트폴리오·새 알림함을 각각 만드는 것보다 낫다. 가장 큰 차이는 서버의 지속 감시, 외부 알림 전달, 변경되지 않는 관측 원본과 후속 결과 기록이다.

기능을 참고해 자체 구현하는 것은 가능하다. 다만 화면에서 본 통계 수치, 모델 검증 성능, 과거 데이터 전체와 서버 운영 품질까지 확보한 것은 아니다. 이를 그대로 재현했다고 주장할 수 없다.

## 2. 조사 범위와 증거 구분

| 구분 | 이번에 확인한 것 | 확인하지 않은 것 |
| --- | --- | --- |
| 직접 조작 | 로그인·프리미엄 표시, 신호 선택과 결과 표시, 신호 설명 창, 수동 포지션·엄격 셋업 입력 행, 구독 구성, 결과 원장과 상세 | 실제 알림 발송·수신, 실제 거래소 계정 동기화, 결제 완료 흐름 |
| 화면의 설명 | 감시 간격, 검증 조건, 키 보관 방식, 데이터 규모, 유료 혜택 | 해당 설명의 서버 구현, 보안 감사, 통계 재현성·데이터 이용권 |

수동 포지션과 엄격 셋업은 입력 항목을 보기 위해 행만 열었다. 저장하지 않고 새로고침했으며, 추가 행이 사라지고 기존 알림 끄기 상태가 유지되는 것을 확인했다. 지갑·API 키를 입력하거나 Telegram을 연결하지 않았다. 계정 이메일과 개인 연결 링크는 이 문서에 보관하지 않는다.

## 4. 신호 탐색 상세

직접 확인한 BTC 화면은 다음 선택 항목을 제공했다.

- 시간봉: 1m, 3m, 5m, 10m, 15m, 30m, 1h, 4h, 1d.
- 목표 폭: 확인한 1h 화면에서 ±0.25%, ±0.5%, ±0.75%, ±1%, ±1.5%, ±2%.
- 기간: ETF 시대와 전체 역사.
- 결합 범위: 동일 봉, 최근 3·6·12봉.
- 시장 조건: 펀딩 양/음, OI 급증, 롱/숏 쏠림, 롱/숏 청산 우세, 테이커 매수/매도 우세.
- 신호 계열: RSI 일반·극단, MACD 교차, EMA 교차, 볼린저 이탈·압축, 거래량 급증, 스토캐스틱, 20봉 돌파/이탈, 장악형, 해머/슈팅스타, Williams %R, CCI, 3·5봉 연속 움직임. 롱·숏 분류 합계 30개가 표시됐다.
- 결과: 과거 표본 수, 상승·하락 비율, 통상적인 신호 방향과 반대인 경우의 설명, 관심 저장·알림·공유 진입점.

RSI 과매도를 선택했을 때 결과가 갱신되고, 상세 설명에서는 목표 폭별 비율과 수수료를 제외한 EV가 표시되는 것을 확인했다. 특정 숫자가 정확한지 원자료로 재계산한 것은 아니다.

**계산 의미를 그대로 섞으면 안 된다.** 신호 조회 하단은 목표를 못 만나면 마지막 값의 방향으로 분류한다고 설명한다. InvestAI의 현재 연구실은 timeout을 별도 집계하고 선택 방향 도달 비율의 분모에도 포함한다. 따라서 동일한 이름의 승률이라도 두 값은 직접 비교할 수 없다.

InvestAI에는 분석 엔진의 Wilder RSI와 연구실의 최근 14변화 합산 방식 RSI가 공존한다. 조건을 통합할 때 `RSI(14)`라는 이름만 맞출 것이 아니라 계산식·초기화·필요 이력·완결 봉 기준을 명세하고 버전으로 보존해야 한다.

## 5. 프리미엄 알림 상세

### 입력과 연동

1. Telegram 봇 연결 후 연결 상태 확인.
2. Hyperliquid 또는 Lighter 주소 입력.
3. CEX를 선택해 조회 전용 키 입력. 사이트는 KMS 암호화·분리된 읽기 서버를 설명하지만 이번 조사는 그 구현을 감사하지 않았다.
4. 거래소 연동 없이 수동 포지션 등록. 열어 본 행에는 종목과 롱/숏이 있고 진입가·수량 입력은 없었다. 사이트는 이 수동 등록의 주식·원자재에 청산·손실 리스크 알림을 제공하지 않고 반대 신호만 감시한다고 설명한다.

### 알림 종류

| 종류 | 확인한 설정·설명 | InvestAI에서의 완료 기준 |
| --- | --- | --- |
| 시장 기회 + 엄격 포지션 | 체험 자동 추천 / 두 피드 / 알림 끄기, 엄격 셋업 추가 | 조건 성립 이벤트와 포지션 진입 관찰을 서로 다른 유형으로 저장 |
| 엄격 셋업 | 조사 시 선택 목록 9개. 자산·시간봉·방향·월간 관측 빈도 표시 | 검증 버전이 붙은 셋업 카탈로그. 임의의 자산 선택을 검증 완료로 표시하지 않음 |
| 내 포지션 반대 신호 | 전체 또는 특정 자산, 시간봉, 기울기 임계값 | 실제 보유 방향과 반대인지 평가. 자료 부족·지연이면 판단 보류 |
| 시장 기울기 | 보유 여부와 무관한 자산·시간봉·임계 설정 | 최초 로딩·계속 같은 상태·재연결 시 불필요한 반복 통지 방지 |
| 진입 브리핑 | 새 포지션 감지 시 1회, 최대 5개 시간봉 | 동일 포지션의 신규/수정/청산을 구분하고 중복 발송 방지 |
| 리스크 | 화면 기본 설명: 청산 거리 8%, 레버리지 25배, 증거금 대비 손실 60% | 거래소·증거금 방식·실제 포지션 값이 있는 경우만 판정. 이 숫자를 안전 기준으로 일반화하지 않음 |

사이트가 제시하는 표본 N≥30·2σ 조건과 순차 재검증·최근 성과·현재 장세 검사는 서로 같은 기준이 아니다. 수많은 조합 중 좋은 결과를 고르는 과정까지 고려해야 하므로 임계값 몇 개를 구현했다고 검증된 우위가 생기는 것은 아니다.

실제 봇 연결·발송·수신과 거래소 동기화는 수행하지 않았다. ‘화면에서 설정 가능’과 ‘운영 신뢰성 확인 완료’를 구분해야 한다.

## 6. 결과 공개와 유입 구조

공개 원장은 조사 시 전체 8건, 진행 중 2건을 표시했다. 이 작은 표시 표본만으로 장기 성능을 판단할 수 없다. 종료 승률과 평균 관찰 결과가 함께 표시되어 승률만으로 결과를 설명하지 않는 구조는 참고할 가치가 있다.

개별 ETH 상세에서 확인한 항목은 차트, 시장/거래소, 조건과 버전 식별자, 진입·익절·손절·손익비, 순차 재검증·최근 가중·시장 상태별 표본, 검증 기간, 유지 봉 수, 결과, 해시 표시였다. 원장 설명은 다음 봉 시가 진입, 비용 차감, 동일 봉에서 목표·손절 동시 도달 시 손절 우선이다. 이것은 표시된 **가격 관찰 규칙**이며 실제 거래소 체결이나 사용자 실현수익을 검증한 것이 아니다. 해시가 보인다는 사실만으로 원본 불변성이 입증되는 것도 아니다.

InvestAI는 ‘알림 발생 원본’, ‘가격 경로에서 계산한 관찰 결과’, ‘사용자가 기록한 실제 매매’를 구분하는 것이 좋다. 알림이 발생한 뒤 조건을 수정해 과거 결과가 바뀌지 않도록 규칙 버전·가격 출처·비용 가정·원본 시각을 고정한다. 매수·매도 호가나 체결이 없는 가격 관측 결과에는 실현손익이라는 이름을 쓰지 않는다.

유입 구조는 무료 시장 정보·계산기 → 무료 알림 체험 → Premium 알림 → 결과 원장 → 다시 알림 설정으로 이어진다. 구독 화면에는 월 USDC/USDT 30, BFC 27, 연간 20% 할인, 거래소 추천 조건에 따른 이용 혜택이 표시됐다. 이는 조사 시 화면 가격이며 구매·혜택 검증이나 수익성 판단은 하지 않았다. 프리미엄 설명의 ‘품질 통과 32자산’과 수동 등록 메뉴의 전체 자산, 실제 선택 가능한 엄격 셋업은 서로 다른 범위다.

InvestAI의 초기 홍보 메시지는 ‘승률 좋은 AI’보다 **지난 검토 이후 무엇이 달라졌는지, 저장한 기준이 지금도 유효한지 확인하는 서비스**가 현재 코드와 더 잘 맞는다. 장래의 외부 알림이 완성되면 이 메시지에 지속 감시를 추가할 수 있다.

## 7. 따라 만들기 전에 바로잡을 부분

- **지표 메뉴의 실제 동작:** ETF 메뉴와 `/setups?ind=etf` 직접 접속에서 공포·탐욕 화면이 나왔다. OI 메뉴에서도 같은 화면이 관측됐다. 조사 세션의 현상으로 기록하며 모든 사용자에게 동일한 결함이라고 단정하지 않는다. ETF·OI 전용 페이지의 정상 동작은 미확인이다.
- **시점 표시:** 현재 가격 표시와 함께 일부 신호에 2일 전 자료 표시가 나왔다. 자료마다 시각과 유효기간을 표시하고, 오래된 조건을 현재 유효 신호로 오해하지 않게 해야 한다.
- **설명 범위의 불일치:** 방법론 페이지는 일봉·초단타 제외·BTC 중심을 설명하지만 실제 화면에는 여러 종목과 짧은 시간봉이 있다. 종합 모델, 탐색 통계, 실시간 조건, 알림 전략의 방법론을 구분해야 한다.
- **현물과 파생상품:** 사이트의 수동 포지션 안내는 주식·원자재 신호가 Binance 무기한 선물 기준이라고 설명한다. 삼성전자 현물과 관련 합성·파생 상품을 같은 가격·거래시간·위험 모델로 취급하면 안 된다.
- **복잡한 시작 화면:** 신호 30개, 시간봉 9개, 결합·기간·시장 조건을 한꺼번에 보여주면 처음 쓰는 사람의 선택 부담이 크다. InvestAI에서는 첫 검토와 상세 탐색을 나누고 기본값의 근거를 표시하는 것이 적합하다.

## 8. InvestAI 구현 순서와 완료 기준

### 1단계 — 기존 기능을 하나의 사용 흐름으로 연결

우선순위: 가장 높음. 공개 자료와 현재 코드로 진행 가능.

- 관심종목 → 검토 저장 → 시나리오 설정 → 변화 알림 → 이전 근거와 비교하는 동선을 연결한다.
- 연구실의 USDT 선물 관측과 기존 KRW/현물 기록은 상품 종류·거래소·호가통화를 포함한 식별자로 연결한다. 다른 가격 기준끼리 자동 병합하지 않는다.
- 현물 보유와 파생 포지션을 구분한다. 현재 시나리오는 현물의 손절 < 진입 < 목표 구조이며 숏·선물 감시에 그대로 사용할 수 없다.
- 앱 전체의 알림함에서 이벤트 이유와 발생 당시 근거를 볼 수 있게 한다. 현재 연구실의 해당 탭 한정 감시와 기존 앱 전경 감시의 범위를 명확히 표시한다.

완료 기준: 새로고침 후 기준 복원, 이전 기록 보존, 조건 수정 시 버전 분리, 중복 이벤트 억제, 오래된 시세에서 판단 중지, 서로 다른 시장을 잘못 연결하지 않는 검증. 화면 수가 아니라 처음 방문과 재방문 흐름을 실제로 따라가며 확인한다.

### 2단계 — 종료 후에도 동작하는 서버 감시와 외부 알림

우선순위: 유료 가치에 가장 직접적. 운영 서버·사용자 식별·저장소·알림 채널 설정 필요.

- 서버가 수집·정규화 → 조건 평가 → 이벤트 저장 → 전달 큐 → 채널 발송을 수행한다.
- 반복 실행, 서버 재시작, 전달 재시도에도 같은 이벤트를 여러 번 보내지 않도록 식별자와 재시도 상태를 보관한다.
- 사용자별 규칙·연결 상태·일시 중지·해제·보관 범위를 구현한다.
- 공개 지갑 지속 조회와 CEX 키 연동을 분리한다. CEX는 서버의 암호화 키 보관, 권한 검사, 키 삭제·교체, 접근 제어가 완성된 뒤 제공한다.

완료 기준: 브라우저 종료 후 테스트 조건 감지, 재시작 후 상태 복구, 다른 사용자에게 잘못 전달되지 않음, 네트워크 실패 후 재시도·중복 방지, 알림 중단 즉시 반영. 실제 채널 연결과 테스트 발송은 별도 사용자 설정 후 검증한다.

### 3단계 — 신호 조합·결과 원장·장기 검증

우선순위: 신뢰성과 차별화. 데이터 확보가 선행.

- 신호 정의를 공통 엔진으로 모으고 30종 패턴, 9개 시간봉, 결합 창, 기간·시장 조건을 지원한다. 지원하지 않는 데이터 필터는 사용 불가 사유를 보여준다.
- 캔들뿐 아니라 해당 과거 시점의 펀딩·OI·롱숏·청산·현물/선물 조건을 보관한다. 현재 지표를 과거 모든 봉에 적용하지 않는다.
- 표본 중복, 누락 봉, 시간 정렬, 다음 봉 진입, 비용, timeout, 목표·손절 동시 도달 규칙을 명시한다. 탐색용 비율과 독립 검증 성능을 구분한다.
- 기간을 나눈 평가·순차 재검증·여러 조합을 검색하는 편향을 다루고, 표본 부족 시 판단 보류한다.
- 원본 이벤트를 고정하고, 목표 도달·반대 경계·기간 종료·자료 부족을 모두 기록한다. 실패한 결과도 같은 원장에 남긴다.

완료 기준: 같은 데이터·같은 버전에서 결과 재현, 미래 자료 미사용, 누락·동시 도달 처리 검증, 비용 가정 표시, 계산 결과와 전달된 알림의 연결. 1,000개 시간봉으로 1년 과열도나 장기 성능을 대신하지 않는다.

### 4단계 — 자산·데이터 확대와 상품화

- 주식·원자재의 실제 시장과 파생 상품을 분리해 거래시간·통화·휴장·데이터 권한을 적용한다.
- ETF 확정 흐름, 경제 일정, 청산 집계, Bithumb·은행 환율·입출금 네트워크 상태를 공급원별로 확보한다. API가 있다는 사실과 서비스에 필요한 이력이 있다는 사실은 별개다.
- 검증 가능한 수집 기간을 확보한 뒤에만 1년 과열 점수를 제공한다. 아직 모으지 못한 기간을 임의 수치로 채우지 않는다.
- 회원·계정 간 동기화·구독 권한·결제·해지·운영 지원을 구현한다. 결제 버튼만 붙인 상태를 유료 서비스 완료라고 하지 않는다.

완료 기준: 실제 운영 환경에서 데이터 공급·비용·권한·지속 감시·알림·결과 추적을 함께 확인. 공급원과 운영 구성이 정해지기 전에는 전체 구현 기간을 확정하지 않는다.
