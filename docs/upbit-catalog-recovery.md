# 업비트 목록 불러오기 실패 복구

사용자가 배포 사이트의 업비트 목록 불러오기 실패를 보고했다. 확인 당시 검증 브라우저에서는 원화 마켓 296개가 정상 표시되어, 사용자 세션의 정확한 HTTP 오류 원인은 확정하지 못했다. 코드에서 확인한 문제는 일시적인 공개 API 요청 실패가 곧바로 목록 전체를 비우고 수동 재시도만 남기는 점이다.

## 수정

- 업비트 429, 5xx, 네트워크 실패, 응답 시간 초과는 기존 10.5초 요청 간격을 지키며 최대 두 번 추가 시도한다. 429의 `Retry-After`가 더 길면 그 시간을 따른다.
- 실제 네트워크 요청에 12초 제한을 적용해 멈춘 응답이 뒤의 요청을 계속 막지 않게 한다. 제한 대기열에서 기다리는 시간은 이 12초에 포함하지 않는다.
- 418 차단과 다른 영구적인 4xx는 자동 반복하지 않는다. 화면 변경 시 취소된 요청·대기 중 재시도도 취소한다.
- 동일 마켓·동일 모드에서 최근 5분 이내 성공했던 메모리 캐시는 **목록 표시용 별도 값**으로만 제공한다. 실패한 새 카탈로그를 성공으로 처리하거나 분석 근거로 사용하지 않는다.
- 마켓 화면에서 이전 목록·가격의 조회 시각과 현재 시세가 아니라는 안내를 표시한다. 이전 목록에서도 종목 선택과 관심 등록을 유지한다. 다른 거래소·기준통화·모드의 목록은 가져오지 않는다.
- 최초 접속부터 실패해 캐시가 없으면 가짜 목록이나 모의 데이터로 대체하지 않는다. 요청 제한·연결 지연 안내와 재시도를 제공한다.

## 검증 및 한계

429 이후 복구/요청 간격/Retry-After, 네트워크 실패, 지속적인 503의 시도 상한, 418·400·404 무반복, 멈춘 응답의 취소 및 복구, 화면 이탈 취소를 테스트한다. 캐시의 마켓·모드 분리/유효 기간/미래 시각 거부, 실패 시 원본 결과와 표시용 캐시의 분리, 이전 목록 선택/재시도/성공 후 안내 해제를 검증한다. 브라우저에서는 명시적으로 표시한 테스트 데이터로 오류 중 목록 유지와 재시도 후 복구 화면을 확인했다.

`npm run check`: 147개 파일 / 770개 테스트 통과. 린트·타입 검사·배포용 빌드 성공. 기존 린트 경고 3개와 500 kB 초과 번들 경고는 유지한다.

이 변경은 복구 동작을 보강한다. 거래소 자체 장애, 지속적인 CORS·네트워크 차단을 우회하거나 API 성공을 보장하지 않는다. 여러 탭·기기의 모든 요청을 전역으로 통합하는 기능은 포함하지 않는다. 캐시는 메모리에만 있으므로 완전한 새로고침 뒤에는 이전 목록이 남아 있지 않을 수 있다.

[업비트 공식 요청 수 제한](https://docs.upbit.com/kr/reference/rate-limits): Origin 헤더가 있는 시세 REST·WebSocket 요청에는 10초당 1회 제한이 적용된다.
